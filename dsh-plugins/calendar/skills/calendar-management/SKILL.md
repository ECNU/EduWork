# 日历与日程管理

界面与日历工具共用本机数据。先读取再修改，并沿用工具返回的来源、编号及原实例时间。

## 查询和安排

1. 用 `calendar_list_events` 查询用户所需的日期范围。遇到“下周”等表达，按当前本地日期计算范围。需要私人内容时使用 `calendar_notes` 或 `calendar_read_personal`。
2. 新建个人活动用 `calendar_create_event`。整条日程修改用 `calendar_update_event`；重复活动仅改某一次时用 `calendar_occurrence`，传原来的日期和来源。删除整条与取消某一次须按用户意图区分。
3. 笔记用 `calendar_put_note`；私人备注、隐藏、提醒用 `calendar_personal_settings`。省略 `originalStart` 操作整条默认值，提供它操作某一次。该值取自读取结果，不能换成调课后的开始时间。
4. 读回结果，说明实际改动；无法关联或被拒绝的事项单独说明。写操作遵循宿主权限决定。

## 批量导入和更新

用 `calendar_import_source`，避免把逐条创建工具当导入工具。个人导入使用稳定的 `agent:<名称>` 来源和稳定 `uid`，再次导入沿用它们。标题、当前日期与版本号都不用于重新生成编号。

- 默认 `mode:'merge'`，只更新本次提供的记录，不按缺席删除。
- 只有确认拿到全部有效数据且用户要求替换时才传 `mode:'replace'`；它会移除本来源未列出的事项。空数组完整替换会清空该来源，执行前应明确这个结果。
- 失败、缺页或无法解析的数据不提交成完整结果。日期改变时保留原实例关联 `movedFrom`；无法确定就报告，交由用户处理。
- 版本化数据传递其递增整数 `revision`。同一版本只能重放相同数据，不能用降版本或删掉版本字段绕过拒绝。
- `sync:` 是数据插件管理的来源，只有宿主明确允许后工具才可更新。无权更新时保留原数据，不另造同名来源绕过。

## 私人设置与提醒

学校说明和私人备注分别保存。`clear` 恢复继承；`off` 关闭某字段；隐藏只影响显示。清笔记不会删除提醒。

提前提醒按实际开始时间计算；固定时间提醒保持指定时间。停课保留笔记并取消对应上课提醒计划。到点后会生成应用内提醒记录，桌面端可通过系统通知提示，无需新建会话或运行模型。需保持应用运行；重启仅补发最近24小时内的到点提醒。系统通知受应用和系统策略影响，不把保存设置或桥接接受说成用户已经看见通知。

## 机构参考资料

若技能末尾列出发行版参考资料，涉及学校学年、考试周、假期或修订时先读取对应资料。路径相对本技能目录解析。按资料标明适用学年和官方依据；学校数据的初始化由机构插件完成，无须用户先聊天。参考资料不覆盖权限与批量更新规则。
