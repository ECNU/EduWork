# EduWork 扩展入口

[English](README_EN.md)

在 DSH 原生左侧“插件”页中增加“EduWork 扩展”页签，统一管理批注、侧聊、文献、邮件、远程访问与外部智能体。只显示当前安装中实际可用的包。

停用会卸载该插件的运行服务和界面，不删除配置或数据；重新启用可继续使用。邮件收取、远控连接等业务开关仍在各自设置中，加载插件不会自动开启这些服务。

## 边界

- 入口随产品提供，独立于被管理的包，停用扩展后入口仍在。
- 通过官方 `listBundles` / `setBundleEnabled` 管理整包。兼容检查、权限、配置持久化及热重载由 DSH 负责。界面展示失败和需要重启的结果，不乐观地假定已经运行。
- `lib/catalog.js` 只保存名称、双语介绍、说明链接及首次预装默认值。产品装配必须先取得已发布 npm 包的精确锁；没有锁的源码包不会被装入正式产品。
- 公版默认加载既有插件，外部智能体默认不加载。发行版可在装配配置中用 `extensionDefaults` 按 npm 包名设置布尔默认值，详见[构建指南](../../docs/BUILD.md)。默认值只负责初始化：已有用户的选择优先，重启、升级和发行版修改默认值都不重置开关。
- 邮件、文献从固定装配改为可选包，迁移保留原生 bundle 列表中的选择。用户启停仍由 DSH 原生 profile manifest 记录，不另建用户开关存储。
- 机构登录和 Memory 保持内置：前者承载机构身份与模型接入，后者还配置共享存储和历史检索。它们不进入此可选目录，也不接受 `extensionDefaults` 覆盖。
- 桌宠继续内置，沿用设置和托盘中的显示／隐藏操作。桌面壳的窗口、托盘及设置入口尚未随插件卸载联动，不在此处增加停用开关。
- Knowledge Studio、决策工具和成果服务保持既有装配，不进入本轮可选目录。Studio 和成果服务的 Skills 由产品集中加载；决策插件在服务启用时自行注册 Skill。未来开放时须验证工具、Skill 发现、技能菜单及用户偏好同步启停。
- 成果服务、通知通道、权限、凭据存储等共享基础设施不列为独立开关。批注和侧聊可分别启停。
- 本页不安装外部 CLI、不启动智能体、不管理凭据，也不改变任务权限。

## 插件配置

插件启用后可通过官方 Slot API 向 `eduwork.extensions.config` 注册 keyed 组件，key 为 npm 包名。它使用普通 `renderSlot` 生命周期，停用时由 DSH 撤销组件。插件可以把同一表单注册到官方 `plugins.bundle.config`，供独立 DSH 安装使用；设置页也可复用该表单。尚未提供此 Slot 的插件保留原设置入口，不显示无内容的“配置”按钮。

新增目录项时，应先完成包发布和锁定，并验证默认关闭、启停、重启、已有用户偏好及配置组件销毁。此产品界面在当前 0.2.2 构建流程中启用，不向旧内核分支回填。
