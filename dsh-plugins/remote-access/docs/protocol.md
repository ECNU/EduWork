# 远程接入协议 v1（`eduwork-remote/1`）

这份文档描述**远端设备**与**本机宿主**之间的契约。它不依赖任何特定学校、机构域名或公共服务：
中继是可选组件，设备配对完全在本机完成，协议本身只假设「有一台跑着 DSH 的机器」。

## 1. 角色

```
远端设备 ──► 门禁中继 ──► 宿主（DSH，只监听回环）
（浏览器）   （本机）      （本机）
```

| 角色 | 职责 | 不做什么 |
| --- | --- | --- |
| **远端设备** | 出示设备凭据；携带 `requestId` 发起有副作用的调用 | 不接触宿主令牌；不管理宿主 |
| **门禁中继** | 准入门禁、配对、逐设备撤销、切断活动连接 | 不重发请求；不代为去重；不改写载荷 |
| **宿主** | 持有会话与工作区；按 `requestId` 保证至多一次准入 | 不对网络暴露 |

**中继是可选组件。** 同 LAN、自建 VPN、端口转发都必须能在没有中继的情况下工作；
协议不假设任何特定外部服务存在。

## 2. 凭据

四类凭据**彼此独立，不得混成同一个令牌**：

| 凭据 | 作用 | 生命周期 | 存放 |
| --- | --- | --- | --- |
| 配对邀请 | 「允许一台设备接入一次」 | 一次性，短时 | 只存摘要 |
| 设备凭据 | 「我是哪台设备」 | 长期 | 只存摘要 |
| 中继接入 Key（可选） | 「允许使用这台中继」 | 部署级 | 由自托管中继自行决定 |
| 宿主会话 | 「宿主认这个浏览器」 | 由宿主决定 | 宿主自己签发 |

关键点：**中继接入 Key 只表示「允许使用中继」，不能代替设备配对。**
即使中继要求接入 Key，每台设备仍然必须完成一次性配对并经本机确认。

## 3. 控制面：`/__remote/*`

控制面由中继自己应答，**永不转发给宿主**。

### `GET /__remote/pair?token=<邀请码>[&name=<设备名>]`

兑换一条一次性配对邀请。

- **成功** → `302`，`Set-Cookie: eduwork_device=<设备id>.<密钥>; HttpOnly; SameSite=Lax`，
  并跳转到宿主自己的令牌交换地址。
- **失败** → `403`。

失败有四种成因：邀请码不存在、已被使用、已过期、写错了。
**四者必须不可区分** —— 实现上「先消耗、再校验」：
无论哪种情况，邀请都已被消费，因此重放、迟到与错字留下的状态完全相同。
响应内容不得泄露是哪一种。

### `GET /__remote/devices`

列出已登记设备与活动连接数。**仅供本机查看**，不是远端的接口。

## 4. 数据面

除 `/__remote/*` 外的所有路径。

| 设备状态 | 响应 | 请求是否到达宿主 |
| --- | --- | --- |
| 无凭据 | `401` | **否** |
| 凭据无效 | `401` | **否** |
| 待确认 | 挂起，等本机决定 | 决定为「是」之后才到达 |
| 本机拒绝 | `403` | **否** |
| 已撤销 | `401` | **否** |
| 已信任 | 转发 | 是，`Host` 改写为回环 authority |

**门禁在宿主之前。** 「未授权设备不能访问会话或文件」这条验收，
只有在拒绝发生在请求**穿过门禁之前**时才成立 —— 若 `401` 由宿主发出，
说明请求已经到达宿主，这条验收就是假的。

被转发的请求，`Host` 必须改写为中继所连的回环 authority：
设备自己的地址不是宿主信任的 authority，原样转发会被宿主的信任围栏拒绝。

## 5. 撤销

撤销一台设备是**三个动作同时生效**，缺一不可：

1. **删除**它的设备凭据（不是禁用 —— 让「已撤销」与「无法认证」成为同一个状态）
2. **封住**它的设备 id，使撤销瞬间正在握手的连接失败而非溜过
3. **切断**它当前持有的全部连接，包括 WebSocket 与 SSE 流

第 3 条不能省。上游语义明确：*已有的请求在监听器拒绝后续请求时仍会继续*。
一条已经建立的流比一次请求更糟 —— 它会**持续推送事件**，
直到有人把它关掉。只拒绝下一个请求，等于让被撤销的设备继续看着你的会话。

## 6. 幂等

**有副作用的调用必须携带客户端生成的 `requestId`。**

宿主按 `requestId` 保证**至多一次准入**，且查重覆盖两处：

- 已入队但尚未执行的
- 已落进会话历史的

第一处覆盖的正是最危险的窗口：**请求已经到达宿主，回执在断线中丢失**。
此时设备重发同一个 `requestId`，宿主返回已接受而**不执行第二次**。

因此中继的责任是「三不」：

| 不做什么 | 为什么 |
| --- | --- |
| **不重发** | 重发会把一次丢失的回执变成第二次执行 |
| **不改写** | `requestId` 是重试与原始发送之间唯一的联系，改写等于静默关掉去重 |
| **不代为去重** | 中继若自己吞掉第二次，就把一次**真实的二次发送**藏了起来；只有宿主有资格判断它是不是重复 |

## 7. 版本

当前版本标识 `eduwork-remote/1`。

协商规则沿用仓库既有取向：**未知版本、冲突标志或缺少关键能力必须报错，
不在授权失败后自动降级。**

## 8. 明确不在 v1 范围内

- 远端**不得**访问宿主管理面：配对管理、凭据读写、插件装卸、终端、`workspace:write`。
  这一条是硬闸，与设备记录里写了什么无关。
- 不定义只读／可操作的角色体系 —— 首阶段所有已配对设备都是「本人的操作端」。
- 业务内容的端到端加密不在 v1；v1 的前提是设备与宿主之间的信道由部署方保证
  （同 LAN、自建 VPN 或自建中继的 TLS）。
