# DSH 0.2.2 集成

[English](CORE-022_EN.md)

构建配方选用 DSH `0.2.2-rc.1`，上游提交 `66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`。`config/desktop-build.json` 指向[候选锁](../third_party/dsh/candidate-v0.2.2-rc.1/LOCK.json)，分别固定 npm Runtime、已发布插件和 Host/Electron 源码输入。产品版本独立于内核版本；切换配方不会发布安装包或修改更新源。

## 用户界面与功能

沿用官方的移动端布局、引用文本、发送失败草稿保留、消息菜单、历史复制、插件详情与更新、文件预览及统一自动化任务界面。新实验能力仍由官方插件管理页控制，发行版已有的身份、遥测和反馈策略继续生效。浏览器仍保持既有接入方式。

上游 Web Fetch 现在使用进程代理策略并允许访问内网地址。需要限制模型可访问网络范围的部署，应在网络层配置出站策略；此次适配不另加一套抓取实现。

[批注](../packages/dsh-annotation/README.md)在新内核使用原生选区操作菜单，与官方“引用文本”和可选侧聊共用菜单。输入框、原生引用、发送与历史恢复仍由 DSH 管理。编辑批注所需的完整语义坐标通过只读 `draftSnapshot` getter 获取；该 getter 尚未写入上游公开 SessionInput 类型，升级时必须复核，缺失或坐标不一致时保留草稿并拒绝编辑。

设置导航图标改用官方 `settings.section.icon` 插槽，卸载后按官方机制回退；删除当前配方对设置导航 Runtime 的补丁调用。桌面文件保存、原生拖出文件和启动诊断报告接入官方桌面模块。应用关闭后的 Host 退出采用上游实现，不再叠加旧的强制退出适配。软件更新的下载、校验、差分与安装机制保持现有实现。

## 插件兼容

- Cordis 升到 4.1；独立 npm 包显式声明 rc.1 兼容，旧开发锁继续用于验证原受支持宿主。
- 工具执行从单次调用改为批次执行器。Studio/媒体的嵌套 Office 调用使用共享成果服务的 `executeGovernedTool`，由官方 ToolExecutionPipeline 保留审批、取消、步骤准入及父/根调用身份；旧宿主仍走旧接口。
- 成果收集使用官方 Agent 轮次边界，不再访问已移除的 Session Projection 状态入口。文献和侧聊的运行时验证同步使用官方工具流水线。
- 自动化任务按 Host 统一管理。退出检查继续读取持久化目录，包含没有加载 Agent 的会话，避免遗漏仍可触发的任务。
- 外部智能体的 Codex/ACP provider 必须匹配宿主版本，不能在 rc.1 宿主中安装另一份旧内核；开发锁与产品装配锁各自验证。

独立插件先发布 npm，再核对版本、来源提交、tarball SHA-256 与 integrity 后更新产品精确锁；不以本地源码覆盖已发布插件。见[包维护](PACKAGES.md)。

## 仍保留的适配

搜索一致性、客户端模块 ctime 误重载、用户消息批注装饰、文件引用卡片及 Creator 可用性适配仍需保留，按已核对的源码哈希或唯一锚点执行。文件引用适配只处理 reference，不改原生 quote。Creator 仍尊重产品开关，不自动启用被用户关闭的能力。

现有设置、账号、会话和用户选择继续迁移；新功能默认值不能覆盖用户已保存的选择。历史组合见 [0.2.1 集成说明](CORE-021.md)。

## 验证边界

构建入口见[构建指南](BUILD.md)。源码集成 CI 验证锁、Host、Windows/macOS Electron 桥接和已装配产品；插件检查使用合成身份、检索与模型输入。原生拖放至外部程序、真实机构登录、模型服务及正式安装包升级需要独立验收，不能用服务注册或合成冒烟替代。
