# 从旧客户端导入历史数据

在新客户端的 **设置 → 通用设置 → 导入历史数据**，点击“选择旧客户端目录并检查”。选择包含可执行程序与 `data` 文件夹的**程序根目录**，不要直接选 `data`。请先退出来源客户端，避免检查期间仍有写入。

检查结束后，先查看来源版本、发现的会话格式、可导入数量和无法导入清单，再点击“导入 N 个可读会话”。只有确认后的会话会合并到当前历史；取消会清除本次临时转换文件。

## 版本如何判断

客户端版本（如 `0.2.0`）仅作辅助信息；缺少 `release.json` 会显示“未标注”，不影响读取。兼容性以每个会话文件头的格式版本为准，并核对文件名中的版本和所在目录的会话 ID。

当前使用 DSH `0.1.5-rc.2` 的官方格式目录及 `v0 → v1 → v2 → v3` 迁移链。检查包含完整正文的严格解码，随后将转换结果写入本次临时区；合并时使用这份已检查的快照。普通 JSONL 和 DSH 多帧 zstd 日志分别解码，截断、损坏及未知版本都不能通过恢复或忽略记录来冒充完整导入。

旧 v0 会话中还可能有独立版本号为 v2 的子代理描述。已对照官方旧源码确认：描述 v3 只增加可选的思考强度字段，因此导入器会保留 v2 原有字段并转换为 v3，再走官方严格校验。未知字段和其他未知描述版本不猜测转换；原始文件不修改。导入说明会列出兼容处理的数量。

同一会话目录存在多代文件时只检查最新代，旧代计入说明；最新代不支持或损坏时，不自动退回旧代。同一代出现两份不同编码的文件也会提示无法确定来源。未知文件布局、版本标记不一致及正文损坏会逐项列出。其余可读会话仍可单独导入，结束时明确标注有未导入项。格式过新会提示更新客户端。

这不代表兼容任意历史版本或任意插件数据库。当前本地回归覆盖带旧子代理描述的 v0、v1/v2 到 v3、v3 多帧压缩、未来版本、损坏正文和压缩尾部、重复与冲突。

适用于旧版 ChatECNU Work、EduWork 的 Go 和 Electron 版，也适用于把另一台电脑的客户端目录复制过来后合并。

## 导入什么

- 历史会话。重复内容跳过；同一会话出现不同历史时保留独立副本，不覆盖当前会话。
- 程序目录内的工作区和附件。工作区随会话登记，同名不同内容文件保留为独立文件。
- 中文、空格目录，未压缩或 zstd 压缩的 DSH 日志，均由官方日志接口读取。

原客户端数据保留，现有模型配置、API Key 和登录信息不变。浏览器缓存、日志、记忆数据库不进行跨机合并。程序目录之外的项目资料不会自动复制；在另一台机器找不到时，仍导入会话，在本机 `dsh/imported-workspaces/` 建立空工作区并重新关联历史，同时在导入说明里提示补拷项目文件。不会因为缺少工作区就丢弃对话，也无法恢复未带来的项目文件。

## 查看结果

界面显示进度、新增和跳过的会话数、冲突副本及异常说明。详细记录保存在当前数据目录的 `dsh/imports/`。导入完成后，先结束当前任务，再重新打开客户端查看会话。

中途退出后可以再次导入同一个目录。已完成并记录的会话会跳过；遇到无法确认是否完成的记录时保留副本，优先保护历史。来源目录中的链接不会被跟随，当前客户端自身不能作为导入来源。
