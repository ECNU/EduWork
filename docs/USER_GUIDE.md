# 使用与配置

EduWork 是单机工作助手。Web 入口用于本机开发验证，桌面版也只操作当前用户的数据，不是多人共享服务。

## 开始使用

1. 解压完整桌面目录，运行对应的可执行文件。Windows Electron 包同样是绿色版。
2. 打开设置中的模型页，选择服务商，填写自己的 API Key、接口地址和模型。支持的模态、上下文与推理档位应按服务商实际能力配置。
3. 选择工作区，开始对话。文件生成、预览、下载与 Studio 使用同一套公共能力。Studio 默认折叠，用户主动开关后会记住偏好。

不需要学校账号。公版保留技能管理、蓝/红配色、个人概览、邮件助手、本地记忆、浏览器、文献检索及 Studio；不包含校内搜索、校内配额或活跃心跳。图像生成和云端 TTS 可通过[通用媒体配置](MEDIA.md)启用，默认不连接云端媒体服务。Wiki 当前不随产品装配。

## 企业登录（可选）

设置中的学校/企业服务页展示已配置的企业。点击“打开配置文件”，由系统选择编辑器打开安装目录的 `config/eduwork.jsonc`。没有文件关联时由操作系统提示选择应用。

默认文件含逐行注释与完整企业示例。更多例子见旁边的 `config/examples/`；源码对应 `config/desktop/examples/`。修改后从托盘退出，再重新启动。

- `organizations: []`：只使用自己的模型。
- 只有 `oidc`：标准 OIDC 身份登录，不要求企业提供模型。
- 增加 `keyBinding`、`provider`：通过 EduWork 资源协议取得 Key 和模型目录；服务端实现要求见本仓库 OIDC 模块的[服务端完整契约](../packages/dsh-oidc/docs/server-integration-contract.md)和[公共资源协议](../packages/dsh-oidc/docs/public-resource-protocol.md)。它们是协议的维护入口，产品文档引用同一份标准。
- 可配多家企业。身份分别保存，运行凭据引用统一为 `EDUWORK_API_KEY`；不用手动复制企业 Key，也不将秘密写入配置文件。

只有 ECNU 版附带具体学校部署示例和专有服务。配置登录不会限制个人模型。企业没有提供某项能力，就不显示该能力。

## 搜索

普通搜索统一调用 `web_search`。配置了 DeepSeek 搜索 Key 时使用 DSH 官方 DeepSeek 搜索；没配时直接使用免 Key 的内置浏览器搜索。不会拿企业 Key 猜测 DeepSeek 的凭据，也不需要更换聊天模型。

官方插件设置 `web-search-deepseek` 可设置 Key 引用（默认 `DEEPSEEK_API_KEY`）、搜索接口和模型。DeepSeek 搜索使用 Anthropic-compatible Messages 接口，其地址与聊天接口不同。添加或移除 Key 后下一次搜索即生效。有 Key 但服务报错会显示真实错误，Agent 可按浏览器技能尝试页面搜索；不会捏造结果。浏览器被验证码拦截时需要用户处理。

## 本机资源与文件

完整桌面装配包含 Python、Office 所需依赖、媒体浏览器与轻量 ASR 资源；纯源码 Web CI 不包含这些大文件。ASR 为本机转写，TTS 可用操作系统已安装语音。可用性以工具查询结果为准；本地语音的中文质量取决于模型、系统语音和音源。

对话与 Studio 共用生成及预览服务。支持报告、思维导图、演示文稿、数据表、测验、闪卡、音频和视频。Office 预览是本地渲染结果，不承诺与所有 Office 软件像素一致。思维导图可交互查看与导出；音视频的 SRT/VTT 是可单独下载的字幕文件。

关闭窗口默认收起到托盘。托盘可打开应用、新建会话、检查更新、打开设置或退出。普通 HTTP(S) 链接在系统浏览器打开。移动绿色目录前应完全退出；外部工作区文件仍在原位置，不随应用目录自动搬动。

用户配置、会话、工作区引用和本机凭据不能当作构建缓存删除。不要同时启动两个程序写同一个数据目录。修改品牌文字或 Logo 只需配置；EXE 图标和应用标识需要重新装配。

## 模型请求总并发

在“设置 → 通用设置 → 模型请求总并发”设置当前客户端可同时发送的模型请求数量，默认 3，范围 1–64。填 2 就最多 2 路；主会话、普通/后台/嵌套子代理和辅助模型请求共用上限，超过的按请求到达顺序排队。多个工作区和主会话也共用这一个上限。

代理数量与模型请求数量不同：可以创建 6 个代理，其中只有部分正在请求模型，其余可能在等待模型、执行工具或等待结果。代理列表的“正在运行”表示任务未结束，不代表正在占用模型请求名额。工具执行期间释放名额，因此总并发设为 1 也能逐步完成子代理任务。

保存后生效。调低上限时，已经发出的请求会正常完成，新请求等待名额；调高时会继续处理排队请求。旧版“子代理最多 2 路、主会话 1 路”的偏好升级后换算为总并发 3，保留原总量。

此设置限制通过当前客户端 DSH LLM 服务发出的请求，不是账号级限流。另开的客户端、外部程序或脚本直接请求 API，以及图像生成、TTS 等独立媒体接口不在这个队列内；账号级总量仍由服务端控制。

## 导入历史数据

在设置中选择“导入历史数据”，选择旧客户端的程序根目录（包含程序和 `data`），先检查可导入项目，再确认合并。请先退出旧客户端；重复会话会跳过，冲突副本和不兼容格式会单独列出。客户端目录外的工作区文件需另行复制，导入不会复制登录凭据。格式识别、合并规则和跨机工作区处理见[数据导入指南](数据导入.md)。

## 故障诊断

在“设置 → 通用设置 → 故障诊断”点击“导出诊断”，下载 `EduWork-diagnostics-时间.zip`。Go/Wails 和 Electron 使用相同的诊断导出能力。

ZIP 内包含系统和组件版本、企业模型配置摘要、实际更新状态、启动/迁移标记及近期脱敏日志。`summary.json` 列出缺失、不可读或截断的文件；一个文件出错不会阻止其他信息导出。即使配置文件损坏，诊断服务也会尽量生成报告。日志采集有容量上限，不会把整个工作目录装进去。

诊断包不读取凭据存储、浏览器资料、会话正文、附件或项目文件。转交前可检查脱敏日志中是否还含需要隐藏的业务信息。具体对话问题请另外下载该会话的 **Session log**，将两份文件一并提供；诊断 ZIP 不会自动包含用户对话。

若旧客户端只导出了一个简短 JSON，它仅包含环境摘要，无法补回没有采集的日志。升级后应重新导出诊断。
