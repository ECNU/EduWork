# Windows 安装、便携数据迁移与卸载

本文说明 [#124](https://github.com/ECNU/EduWork/issues/124) 与 [#176](https://github.com/ECNU/EduWork/issues/176) 共有的使用流程：将旧便携版数据迁入标准安装版，并在后续更新、卸载时保留个人数据。是否已经发布安装版，以对应 Release 的实际附件为准。

## 安装和首次迁移

1. 正常退出旧客户端和它的后台任务，保留完整旧目录。
2. 运行 `EduWork-<版本>-windows-x64-setup.exe`。标准安装程序提供安装目录选择、开始菜单和桌面快捷方式，以及系统“已安装的应用”中的卸载入口。它安装到当前 Windows 用户，不要求管理员权限。
3. 为新版选择独立的程序目录。安装程序拒绝覆盖包含个人数据的旧便携目录；从兼容包进入时会避开已有便携数据的默认位置。安装后直接从新快捷方式启动。
4. 首次启动选择“迁移旧便携版数据”，并选择包含程序、`config`、`data` 的旧根目录。也可以明确选择“全新开始”；首次选择前不会初始化个人数据目录。
5. 检查来源版本、目标版本、文件数、数据量和目标位置，再确认开始。程序检查相关进程、版本与组件、目录冲突、未完成更新和磁盘空间；复制后逐文件校验 SHA-256，再启用新版数据目录。
6. 新版重新启动后，检查历史会话、附件、记忆与遗忘记录、工作区、设置和插件，并确认凭据与登录状态。退出后再启动一次。完成后可在托盘的“旧版数据迁移”中选择“已检查数据，确认迁移”。

源目录在复制前会改名为同卷的 `<原目录>.handoff-<随机编号>`，以阻止旧路径再次启动并写入。它包含完整旧程序和旧数据。新版文件校验、启动检查和用户确认是三个独立状态；即使确认完成，程序也不会自动删除这个保留目录。

程序目录与个人数据目录分离：

```text
P  程序目录，默认 %LOCALAPPDATA%\Programs\EduWork
W  个人数据，默认 %LOCALAPPDATA%\EduWork\<distribution>
   W\config                                  用户配置
   W\data\<distribution>-electron\dsh        会话、附件、记忆、插件
   W\data\<distribution>-electron\browser    浏览器状态和加密凭据
   W\data                                    配置、内容更新状态及日志
```

公版的 `<distribution>` 是 `eduwork`。不同发行版不能相互覆盖。程序中的配置只作为模板；用户数据写入 W。数据清单和排除项见[数据清单与兼容边界](DATA-MIGRATION.md)。

## 后续更新

安装版复用锁定官方 Desktop 的更新协调器与 `electron-updater`，通过标准 NSIS 安装程序替换程序目录。用户先检查、下载并校验更新，再决定何时安装；确认退出任务后才锁定新任务并停止 Host。更新不删除 W。

兼容便携包仍可由旧 ZIP 更新器安装。兼容包之后使用标准安装器更新，并把旧根目录传给安装程序；安装后的首次启动仍需用户确认迁移。未包含这段能力的旧版本不能直接把 NSIS 安装器当作 ZIP 安装，需手动下载标准安装器，或先更新到兼容包。Release 中的 ZIP 与标准安装器分别有完整性清单。

公版使用 GitHub Release 更新元数据。自托管发行版通过 `updates.windowsFeeds.stable` 的 HTTPS `latest.yml` 和 `updates.windowsFeeds.development` 的 HTTPS `nightly.yml` 配置安装版更新。旧便携 JSON 清单不能用于 NSIS；未配置安装版更新源时保留数据并显示更新不可用，不静默切换机构更新源。

## 卸载与重新安装

手动卸载默认保留个人数据，可重新安装后继续使用。只有在卸载提示中明确选择同时删除数据时，才清除当前用户、本发行版、带有效归属记录的 W。来源保留目录、外部工作区和其他发行版不参与删除。

静默卸载和更新过程中始终保留个人数据。应用仍在使用 W、归属记录不匹配或数据根为目录链接时，清除操作会停止。安装和卸载不强制结束客户端或后台任务。

## 兼容与失败处理

- 当前迁移配置允许检查 `0.4.12`、`0.4.13` 和采用迁移格式 v1 的兼容便携包。来源与目标须同发行版、同 appId、同 DSH 完整版本和提交，以及相同的 Node 与 Electron 版本；装配回执中的全部 npm 插件版本和包哈希也须一致。产品版本可以不同。公版 `0.4.12` 的远程访问插件与当前 `0.4.13` 构建组合不同，会被组件校验拒绝。
- 来源根目录本身不能是目录链接，请选择真实程序目录。安装版程序目录出现额外个人文件、工作区或子目录链接时，更新和卸载会停止，需先将它们移出。
- W 必须不存在或为空。选择“全新开始”后产生的数据、已有安装版数据或不明目录，都不会被旧数据覆盖；需要合并会话时使用[历史数据导入](数据导入.md)。
- 外部工作区不复制、不移动、不删除，绝对路径保持原文。位于旧程序目录内部的工作区会被拒绝，应先单独迁出并确认引用。外部配置、外置插件数据和额外个人文件不属于迁入清单，仍须另行保管。
- 凭据与浏览器加密上下文一同保留，但凭据绑定 Windows 用户或设备。跨用户、换机、令牌过期等情况可能需要重新登录。文件复制成功不代表认证有效。
- 复制、哈希或回执写入失败时，程序尝试恢复旧目录原名，不启用半份数据。强制退出后再次启动安装版，按提示恢复上次迁移；不要删除迁移记录、保留目录或临时目录。
- 新版数据已经启用后，不自动覆盖或删除 W。启动失败时保留 W 和旧保留目录；先退出新版，再从旧保留目录运行原程序可继续使用迁移前的数据。两份数据之后的改动不会自动合并。

## 交付检查

Windows 原生验收必须覆盖：首次选择与取消、旧进程退出、完整数据迁入、凭据解密、退出后冷启动、安装目录切换失败恢复、一次安装版更新、注册表与快捷方式、默认保留数据卸载、主动清除数据及外部工作区保留。合成文件测试、安装脚本编译和构建成功分别记录，不能代替这些应用验收。

开发构建选择 `--data-layout installed` 会生成标准安装器和供旧更新器使用的兼容 ZIP；`portable` 只生成兼容 ZIP。构建流程见[构建指南](BUILD.md)。源码中的迁移脚本与客户端使用同一实现，只用于维护和排查，不是普通用户的操作入口。
