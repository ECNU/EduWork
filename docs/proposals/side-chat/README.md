# 侧边聊天提案

**简体中文** | [English](README_EN.md)

状态：**首阶段已有独立实验实现，尚未进入默认产品；转正仍为计划。** 以下区分当前实验与后续完整方案，不代表正式版本已经交付。

## 当前实验范围

参考 [Codex `/side`](https://github.com/openai/codex/blob/7d592f6dd9988e349e3164feaa21d0fc14bbac8a/codex-rs/tui/src/app/side.rs)，首阶段只做临时侧聊，**没有转正按钮**。从用户消息或已完成的助手回答开启新会话；继承历史仅供参考，只有侧聊中新提交的问题是当前指令，打开本身不调用模型。历史使用普通聊天组件展示，专门的折叠视图尚未实现。

每窗口一个侧聊；同一来源消息再次开启会复用它，其他来源须先关闭现有侧聊。模型配置取截断点前最后一次请求，没有记录时用部署默认值；来源 Agent 预设重新挂载，权限重新判断。禁止子代理、定时任务、长期后台工作、侧聊内再分叉与专属工作树。

消息仅驻留内存，不写入会话持久化、列表、搜索和自动历史记忆索引；浏览器不保存临时草稿、视图偏好或侧聊标签。折叠、切换主会话、成果预览与隐藏窗口保留状态；显式关闭、刷新或真正退出结束侧聊。异常断线通过 45 秒租约及清理轮询回收，关闭失败保留不可续租的清理状态并重试。显式执行的文件修改和外部操作不会回滚。

锁定的 DSH `0.2.1-rc.2` 已支持精确分叉、轮次闭合、Agent 作用域、嵌入聊天和侧栏标签，**官方 npm Runtime 尚不具备完整的临时生命周期契约**。实验增加 `ephemeral` 工厂参数与会话元数据，并在持久化、查询、发现事件和客户端存储中处理它。使用受原始文件哈希保护的 npm 编译产物派生，同时记录对应源码变更和文件回执；只写入新的实验目录，标记 `experimental-side-chat`，不能作为默认 npm 缓存或产品锁使用。正式接入需协调上游契约与兼容版本。

实现与命令见[实验插件](../../../packages/dsh-side-chat/README.md)。自动化覆盖真实 Runtime 的模型循环、历史截断、存储与搜索隔离、普通会话持久化、独立取消、后台工具限制、创建/关闭竞争、租约及清理重试；浏览器脚本使用隔离 Host 和确定性模型验证交互。它们不替代真实服务商、多模态、Office、OIDC 与音视频全流程验收。复杂工具/附件历史、附件失效、来源删除、窄窗口和多窗口仍需专项验收。实验关闭自动更新，不发布 npm，不更新默认组件锁。

## 完整方案目标（计划）

用户可以在原会话的任意一条用户消息或助手消息上选择「开启侧边聊天」，在右侧围绕该处继续追问，同时保留原会话的位置。例如，原会话正在制定课程方案，可以从某条回答分出侧边聊天讨论评分标准，不打断原会话后续的课程设计。

侧边聊天拥有全新的会话 ID、输入框、生成状态和取消操作；以「临时聊天」标识，并显示来源消息入口、关闭和「保存为会话」按钮。它是用户直接操作的独立会话，不作为原会话的子代理，也不自动向原会话回传结果。

## 与普通会话的区别

| 项目 | 侧边聊天（转正前） | 普通会话（含转正后） |
| --- | --- | --- |
| 起点 | 原会话截至选中消息的历史快照 | 新建时为空，或保留转正时的完整上下文 |
| 展示 | 原会话旁的临时面板 | 常规主聊天区域 |
| 目录与发现 | 不进入会话列表、目录、搜索、最近会话和自动历史记忆索引 | 按现有普通会话规则管理 |
| 生命周期 | 明确关闭后删除；不支持重启恢复 | 关闭界面后仍保留，需主动删除 |
| 模型与工具 | 复用普通会话能力、权限规则和全局并发限制 | 按现有规则执行 |
| 保存 | 用户主动选择目录后转正 | 正常持久保存 |

## 后续完整方案边界（计划，含转正）

1. **历史截取。** 携带当前可见会话分支从起点到选中消息（含该条）的上下文，不带入之后的消息；之后双方新增、编辑或重新生成的消息互不影响。继承历史默认折叠，可展开查看。选中用户消息时不自动重跑其请求，由用户发送新的追问。
2. **消息边界。** 所有用户消息、已完成的助手消息均提供入口；不把内部工具事件作为独立入口。正在生成的助手消息须完成或停止后才能开启，避免复制半条输出或不完整工具调用。历史中的工具调用与结果应组成合法的上下文，禁止重新执行历史工具操作。超长历史沿用普通会话的上下文压缩规则，并提示实际采用了压缩；不承诺每次请求都完整发送全部原文。
3. **独立运行。** 默认采用来源会话当前的模型与 Agent 预设，之后可以独立调整。主、侧会话可以同时生成，各自停止；权限按新会话重新判断，不复制来源会话的单次批准、运行中任务、待审批操作或子代理。附件保留可用内容和引用，无法读取时明确提示，不能只复制展示卡片却宣称已携带内容。
4. **关闭与切换。** 首版每个客户端窗口同时打开一个临时侧边聊天。切换原会话或打开成果预览时，只隐藏面板并保留临时状态，返回后恢复；收起不等于关闭。打开另一个侧边聊天前，需明确选择保存现有聊天或关闭并丢弃。关闭按钮、所属窗口关闭以及客户端退出均结束该临时会话，刷新或异常重启不恢复。窄窗口可用覆盖面板，生命周期一致。
5. **关闭即消失。** 明确关闭后立即撤销该临时会话的访问入口，取消其生成、排队请求及其拥有的后台任务，再清理临时消息、草稿和独占缓存。可复用会话存储的临时命名空间，但不能混入普通会话索引；进程异常退出留下的数据在下次启动时回收。只删除临时会话独占数据，不删来源附件。已经发送的邮件、改写的工作文件等外部操作不会因关闭而撤销；临时聊天也不等同于服务商不留存请求。
6. **手动转正。** 点击「保存为会话」，可编辑标题，并从当前有权限使用的任意会话目录中选择，也可选未归类。保存完整继承历史、侧边新增消息及所需附件，成功后保留同一个会话 ID，以普通会话打开；再关闭界面也不会删除。失败或取消选择时保持临时状态，允许重试。生成期间先完成或停止，再转正；保存提交期间禁止并发关闭，重复点击不能生成副本。
7. **目录不等于工作目录。** 转正中的目录选择只改变会话归类，不隐式移动文件或修改工具工作目录。若现有目录实际绑定项目工作目录，必须明确提示并复用项目迁移规则，验证附件与路径仍可用后才算转正成功。临时会话默认沿用来源工作目录，因此两个会话仍可能读写同一文件；会话独立不表示文件系统隔离。
8. **来源与记忆。** 来源关系只用于定位，不作为读取历史的唯一依赖；来源会话被修改或删除后，侧边快照与已转正会话仍可继续使用。临时聊天不自动进入长期记忆或被其他会话检索；用户明确要求写入的外部文件、知识库或记忆按现有权限执行，不随关闭回滚。

首版不做多侧栏、侧边聊天内再次分支、自动合并回原会话、临时聊天跨设备同步或崩溃恢复。需要长期保留时使用转正。

## 后续转正评估

**转正仍需跨层设计。** 首阶段已经验证精确截断、双聊天面板及实验 Runtime 的临时存储隔离，但原子转正、附件独立保留与任意目录归类尚未实现。

计划复用普通会话的消息投影、输入、模型执行、工具权限与附件服务，为会话增加明确的临时生命周期；UI 只负责入口和面板。临时标记必须贯穿后端会话查询、搜索、记忆扫描、导出和通知路由，不能仅在前端隐藏列表。转正需要在正式存储和附件引用均提交成功后才改变会话状态；清理与转正共享状态约束，避免误删或重复保存。

正式接入前需协调 DSH 扩展契约和发布版本，继续核对复杂工具与附件历史、目录与工作目录的绑定关系。保持现有 npm 与组件锁，不能把实验派生冒充官方包交付，也不建立第二套聊天引擎。成果预览与聊天面板复用现有布局能力。

## 后续验收重点

- 从早期用户消息、助手消息及带工具结果的消息分出新会话，核对截断位置、附件和上下文；原会话后续变化不能串入，历史工具不重放。
- 同时生成、独立取消、切换会话与成果预览、收起与显式关闭均符合上述生命周期；关闭后搜索、记忆和重启均不能找回临时聊天。
- 关闭时任务停止，清理失败可重试且不会恢复入口；来源数据不受影响，删除来源后保留的快照仍可用。
- 任意可用目录转正、失败重试、重复点击及保存与关闭竞争不会丢消息、重复建会话或误删附件；转正后重启可以打开完整会话。

上述为完整方案验收项，不能用首阶段测试代替。重点还需讨论转正是否保留会话 ID、原子保存与关闭竞争，以及“任意目录”究竟是独立归类还是改变工具工作目录。
