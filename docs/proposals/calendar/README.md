# 日历与日程模块提案

**简体中文** | [English](README_EN.md)

状态：公版日历、个人设置、来源登记与批量更新和 Agent 读写已实现；提醒已接入到点记录和可选桌面系统通知，不启动模型；真实学校取数尚未接入。代码与用法见插件 [README](../../../dsh-plugins/calendar/README.md)，接入契约见[来源与提醒接口](INTEGRATION.md)。

归属：公版（EduWork）。机构版的数据接入另案，边界见[机构版边界](#机构版边界)。

## 目标

在公版引入一个可独立运行的日历与日程插件：提供周/月视图、本机事件与个人笔记存储、ICS 导入导出，以及一个**开放的数据结构**，供机构版注入学校数据（校历、课表）。课表是日历模块的一种数据来源，不是公版专属概念。

插件可被其他 DSH 应用单独使用，不要求安装 EduWork 桌面端；不引入运行时依赖，不依赖机构凭据、私有网络或相邻机构仓库。

## 插件身份

| 项 | 值 |
| --- | --- |
| 发行标识 | `eduwork-calendar` |
| 包名 | `@eduwork/dsh-calendar` |
| 源码 | `dsh-plugins/calendar` |
| 面板标识 | `calendar` |
| 形态 | 内置源码扩展：装配时从源码构建，不单独发布 npm 包 |

命名取舍：这一能力在公版面向的是"日历与日程"，不是某一所学校的课表；课表与校历都是它的数据来源。上游已有 `@deepseek-ai/dsh-schedule`（提醒引擎）与 `@deepseek-ai/dsh-client-ui-schedule`（会话页头的只读提醒目录），为避免概念重叠，本插件不使用 `schedule` 命名。

可选性：公版插件默认随发行安装。本插件按现有 UI 扩展的方式声明**可整体移除且不侵入核心**（`package.json` 的 `chatecnuWork` 声明：`kind` 为 `ui-extension`、`removable` 为真、`uses` 列出所用槽位）。移除它不影响对话、Studio 与其他能力；是否存在面向用户的开关由设置页既有能力决定，不在本提案内。

## 范围

纳入本提案：

| 能力 | 说明 |
| --- | --- |
| 周/月视图 | 按周安排时间、按月浏览；支持前后翻页、回到今天与来源筛选 |

| 本机事件存储 | 事件仅保存在本机，跨会话保留 |

| 侧栏入口 | 复用现有 `sidebar.panellist` 与 `main` 插槽（已验证） |

不在本提案内：

| 事项 | 去向 |
| --- | --- |

| 议程视图、拖拽调整已有日程 | 后续按需 |

| 课堂纪要、作业等课程挂载能力 | 后续里程碑 |

## 与既有实现的关系

### 官方底座

| 包 | 作用 | 与本文的关系 |
| --- | --- | --- |
| `@deepseek-ai/dsh-schedule` | 宿主侧提醒引擎：一次性、定期间隔与日历规则提醒，跨重启存活 | 提醒（另案）的底座；本提案不复制调度能力 |
| `@deepseek-ai/dsh-client-ui-schedule` | 会话页头的只读提醒目录 | 与日历面板职责不同，不替换它 |

两者都只覆盖"提醒的存在与到期时间"，不提供日历视图、事件存储与数据注入入口，因此本提案与其功能不重叠。

### 第三方实现

调研记录见 issue #48（2026-09-27）。结论是没有现成的课表插件，也没有一个实现同时满足"本地存储 + 提醒 + 数据注入 + 周视图"。与本提案相关的候选类型：

| 候选类型 | 值得参考的部分 | 直接引入的顾虑 |
| --- | --- | --- |
| 多视图日历（周/月/议程、拖拽） | 视图布局与交互设计 | 停在较早的 DSH API 版本线；单人维护；自带数据模型与样式 |
| 以 CalDAV 与 RRULE 为主的日历工具集 | ICS 兼容与 RRULE 展开的实现思路 | 较新版本已不提供 UI；内部模型与本提案的开放契约不同 |
| iCal 订阅与提前提醒类 | 订阅导入的产品形态 | 依赖外部订阅源；提醒通道与本仓库的通知契约不同 |
| 节假日与农历类 | 节假日数据来源 | 校历与调休应以学校数据为准，属机构版 |

引入任何候选前需要重新核对其许可证、版本线与维护状态。

### 复用路径与准入条件

本仓库已有四类成熟的复用机制，都可以用于日历能力，但准入条件不同：

| 路径 | 仓库内先例 | 准入条件 | 代价 |
| --- | --- | --- | --- |
| 参考设计、自行实现 | 多处 | 无 | 无许可与版本负担；工作量集中在视图与契约 |
| 源码内置 | `dsh-host/vendor/jsonc-parser`（保留许可证与 README） | 保留许可证与出处，纳入源码审计 | 需长期跟随上游修复 |
| fork 为独立 npm 包 | `@eduwork/dsh-literature`（fork 自第三方并接续维护） | 迁入 `packages/`、改名、适配 DSH 基线、**发布 npm**、补组件锁；需要维护者配合 | 依赖与发布流程变重 |
| 运行时补丁 | 会话检索回填 | 记录补丁标识、包版本与前后 SHA-256 | 只适用于小范围修复 |

### 本提案的取法：复用设计，自行实现

本提案主张**复用设计、自行实现**，理由：

- 调研结论本身指向这条路径：现成实现都不满足"本地存储 + 提醒 + 数据注入 + 周视图"四条，而其中最完整的候选，覆盖更广的视图与拖拽功能，但缺少本提案需要的来源及个人数据边界。
- 直接引入会把许可、版本线、依赖锁与长期跟进上游的责任一并带入，而本提案真正依赖的开放契约、Host 侧注入入口与通知对接，第三方并不提供。
- 自行实现可以沿用现有主题变量与界面基础组件，风格与现有面板天然一致，不需要"先接入再改造"。

复用的具体内容：只参考信息结构与交互——一周的排布、当前时间与今天的标记、事件块的信息层次、翻周与空状态。视觉与代码在本仓库自行编写。

约束：

- 保持零运行时依赖，与 `dsh-plugins/` 现有插件一致（它们均未声明运行时 `dependencies`）。
- ICS 与 RRULE 只实现[重复规则边界](#重复规则边界)列出的子集，思路参考调研结论，不引入第三方解析依赖。
- 若维护者更希望以 fork 或源码内置的方式复用某个既有实现，请在评审时指定候选，我们按上表对应的准入条件另开提案；这会改变依赖锁与发布安排。

## 事件数据结构

公开契约的核心。字段按 ICS 语义设计，避免绑定任何单一数据源。

| 字段 | 类型 | 必填 | ICS 对应 | 说明 |
| --- | --- | --- | --- | --- |
| `uid` | string | 是 | `UID` | 来源内稳定编号；与 `source` 一起定位日程 |
| `title` | string | 是 | `SUMMARY` | 标题，如"组会""体检"；机构注入的课表里就是课程名 |
| `start` | string | 是 | `DTSTART` | 本地时间 `YYYY-MM-DDTHH:mm`，或日期 `YYYY-MM-DD` |
| `end` | string | 否 | `DTEND` | 全天包含结束当天；计时结束必须晚于开始，起止格式须一致 |
| `location` | string | 否 | `LOCATION` | 教室等地点 |
| `description` | string | 否 | `DESCRIPTION` | 日程自身的备注，会随 ICS 导出；不是私人笔记 |
| `recurrence` | object | 否 | `RRULE` | 见[重复规则边界](#重复规则边界) |
| `exceptions` | string[] | 否 | `EXDATE` | 被取消的实例 |
| `source` | string | 否 | — | 来源命名空间，缺省为 `manual`；不同来源可使用相同 `uid` |
| `originalStart` | string | 否 | — | 非重复日程改期前的原始身份；重复实例从不变基线产生 |
| `extensions` | object | 否 | `X-*` | 未识别字段的原样保留区 |

示例（合成数据）：

```json
{
  "schemaVersion": 2,
  "events": [
    {
      "uid": "demo-event-1",
      "title": "示例讲座",
      "start": "2026-03-02T08:00",
      "end": "2026-03-02T09:35",
      "location": "示例楼 101",
      "recurrence": { "freq": "weekly", "count": 16, "byDay": ["mo"] },
      "source": "manual"
    }
  ]
}
```

约定：

- 本提案主张的是**结构开放**：字段可增、未识别字段原样保留、结构带 `schemaVersion`、新增可选字段不提升主版本。
- 时间存为本地日期或时间。UTC 输入转换成本地时间；不支持的外部时区明确报告，不能静默按本地时间接收。
- 来源名称应跨重新登录保持稳定；不同账号应使用不同来源。适配器不能用临时凭据或会变的展示名称作为身份。
- 公开契约只定义数据形状，不定义存储位置与文件名。

## 为什么公版里没有课程实体

第一版曾把课程作为公开契约的一部分（一张 `courses` 表，事件通过 `courseId` 引用）。现在公版里只有日程这一种记录，理由是课程不是日历的通用概念：

- 日历的数据单位是"某一时刻有安排"，一门课只是这条安排的来源与分组方式。课程表、教师、默认教室属于教务数据，公版不含任何学校专属逻辑。
- 一个"课程"实体只有在有人替它维护教学班、学期与培养方案时才有内容；公版拿不到这些，于是这张表除了在导入导出时往返一次，没有别的用途。
- 机构版把课表作为**数据来源**注入：一条日程可表示重复系列，某一次课是其展开实例；`source` 表示来源，`recurrence` 表示支持的重复规则。同一个"日程"结构因此也装得下邮件、活动与个人安排，不需要为每种来源加一个实体。

将来的课堂纪要、作业与成绩等能力按课程挂载，需要时由机构注入侧提供课程标识（放在 `extensions` 或 `source` 作用域内），不改变公版的日程契约。

## 重复规则边界

`recurrence` 只支持日程与校历真正需要的子集：

- 支持：`weekly`、`interval`、`count`、`until`、`byDay`
- 不支持：`monthly`、`yearly`、`BYMONTHDAY`、`BYSETPOS` 及复杂 `RDATE` 组合
- 不支持的规则在导入时保留原始 `RRULE` 字符串并降级为单次事件，不静默丢弃

"第几教学周、单双周、节假日调休"依赖校历，属于机构版数据；公版只接受"学期起始日期"这类通用输入。

## ICS 边界

导入与导出使用自研的最小实现，不引入第三方日历解析依赖。

- 导入：`VCALENDAR`、`VEVENT`、`DTSTART`、`DTEND`（日期与本地时间）、`SUMMARY`、`LOCATION`、`DESCRIPTION`、`UID`、`RRULE`、`EXDATE`、`RECURRENCE-ID`；行折叠、转义与 UTF-8 按 RFC 5545 处理
- 导出：生成可被常见日历应用读取的最小 `VEVENT` 集合；有单次改动的重复日程同时导出主事件与带 `RECURRENCE-ID` 的单次事件
- 早期形状的 `X-EDUWORK-COURSE*` 与 `X-EDUWORK-NOTE` 属性在导入时识别后丢弃：课程不再是公版概念，它们的取值改为写进日程自身的 `SUMMARY`/`LOCATION`/`DESCRIPTION`，不会随导出再写回
- 单次改动与取消：`RECURRENCE-ID` 指向的那一次写入日程的 `overrides` 或 `exceptions`，不改动系列本身；没有 `RRULE` 的日程直接改写记录，不写单次覆盖
- 不做 `VTIMEZONE` 完整实现、`VALARM`（提醒由通知管道负责）、CalDAV 与订阅
- 导入是显式用户动作，不做后台抓取。面板默认追加或更新；仅用户明确开启移除选项时清理本来源中未列出的日程。
- 组件结构损坏时整次拒绝，任何写入前检查起止配对和完整性。部分条目无法读取时返回原因并禁止缺席清理；合法完整的空日历可用于明确清空本来源。
- ICS 全天结束是排他的，必须严格晚于开始，再转为内部包含结束当天的格式。
- 导出携带来源身份，避免不同来源相同编号在重新导入时合并；私人笔记不写入 ICS。

## 展示层边界

本提案的第一个可交付结论（已完成可行性验证）：

- 公版左侧栏的面板列表插槽是 `sidebar.panellist`，列表槽，由 `@deepseek-ai/dsh-client-ui-sidebar` 拥有。登记项需要 `id`，可选 `order` 与 `label`；行、按钮、提示与高亮由侧栏负责渲染。
- 点击登记项时侧栏调用 `selectPanel(id)`，主区切换到 `main` 插槽中 `key` 等于同一 `id` 的注册项。
- **结论：产品需要的左侧日历入口不需要新增"左侧面板"能力**，复用上述两个插槽即可。
- 侧栏标签文案与是否支持按发行配置覆盖，见[尚待明确](#尚待明确)。

## Agent 读写边界

`lib/tools.js` 通过同一份 `calendar` 服务提供十一个工具：读取日程、新建、修改、删除、改单次，以及 `calendar_notes`、`calendar_put_note`、`calendar_remove_note`。另有按来源批量更新的 `calendar_import_source`；具体参数见插件 README。

- 读取区间有上限，缺省从今天前 180 天到后 366 天，单次最多 3660 天。
- 修改、删除与改单次必须沿用读取结果的 `source` 和 `uid`。写笔记还要使用 `originalStart`，不能用改期后的当前时间代替。
- 整条修改与单次调整分开；省略字段保持原值，调整开始时间保留原时长。
- 写操作复用 `tools/pre-execute` 的会话权限：读取放行，普通会话的写入询问，无审批会话放行，无会话上下文的写入拒绝。
- 工具和面板共用服务层校验。工具已注册并有服务集成测试，真实模型会话是否验收由对应 PR 单独报告。

## 数据形态与存储

Host 持有日程与私人笔记，面板和 Agent 通过同一服务访问。客户端不另存一份日程。

- 日程以 `source + uid` 定位，同编号的不同来源互不覆盖。键编码由 `lib/keys.js` 统一提供。
- 笔记、私人备注、隐藏与提醒在独立的 `calendar_personal` 存储域中保存，引用包含 `scope`、`source`、`uid`，某一次的笔记还包含 `originalStart`。删除或替换来源记录不级联删除笔记。
- 重复系列保留原始开始和重复规则；调课用指向原实例的覆盖表示。缺少原实例信息，或整条重复规则变化时，来源写入返回无法关联并保留原记录。
- 本地事件表的读、修改、提交放在同一写队列任务中；笔记按目标排队。保证限于同一进程，不承诺多进程同时写同一存储。
- 旧来源备注和附加字段归属不明时，首次升级保留待确认备份；新私人内容不再写入来源 `description` 或 `extensions`。
- 兼容开发期间的裸编号和旧组合键；目标键已有记录时不覆盖它。来源不明的旧记录保留并报告 `needsReview`。

插件不主动上传数据。Agent 工具读取的内容会进入当前会话。机构凭据由机构侧处理，公版日程和笔记不保存令牌。

## 提醒边界

个人提醒设置已独立持久化，支持整条默认、单次覆盖、恢复继承和显式关闭。相对提醒按当前实例时间计算；调课与跨天后重算，停课后停止上课提醒。固定时间提醒保留用户指定时间，不随调停课改变；它是独立的个人安排。

`reminderPlan` 生成稳定任务编号，`registerReminderScheduler` 向可替换的 Host 调度适配器提交完整计划；重复计划不重复提交，变更与取消按同一编号替换。适配器负责持久化、按编号去重和实际投递。默认 Host 投递复用这些计划并持久化到点回执，通过已有桌面通道显示系统通知；浏览器提供应用内记录。

DSH `schedule` 的会话提醒与本模块的系统通知路径独立。日历系统通知无需会话或模型，应用运行和通知策略仍是前提。具体契约见[来源与提醒接口](INTEGRATION.md)。

## 机构版边界

- 公版不含任何学校专属逻辑：不含教务系统地址、抓取实现、校历与节假日规则。
- 来源通过 `calendar.registerSource` 注册稳定提供方、账号与逻辑来源，返回限定来源的写入对象。数据插件负责取数、定时、超时、登录与重连重试；公版保留启停、过时提交保护、版本校验和各来源状态，区分完整与增量写入。
- 机构版按[发行版边界](../../EDITIONS.md)在 `edition/plugins/` 提供适配器：把学校数据转换为上述公开结构，并通过公版提供的 Host 侧入口注入。
- 机构版升锁依赖公版**发版**：装配在机构模式校验公版提交与源码回执，因此机构集成在公版合入并发布后进行，不在本提案内。
- 学校格式暂不固定；机构插件自行处理真实登录和联网事件，取数并转换成通用来源批次，再通过来源写入接口提交。公版不预设学校接口。
- 校历与课表目前共用日历面板，可按来源筛选；机构注册两个入口并指定默认视图的能力仍是后续方案。
- 离线路径同样可行：机构侧把教务系统页面另存后解析为 ICS 或上述 JSON，再走通用导入，不依赖校方接口。

## 兼容性边界

- 新增一个独立插件，不修改现有插件的公开导出、配置标识和数据路径。
- 不新增运行时依赖，不改依赖锁，也不新增需要单独发布的 npm 包（内置源码扩展在装配时重建）。
- 需要评审的公开接口有两处：日程数据结构，以及客户端半读取与写入数据的远端方法面（当前 19 个方法）。两者都定义在 `lib/typert-schemas.js` 与 `lib/typert-descriptors.js`，主机与客户端共用同一份描述。
- 发行清单新增一行插件登记，不改变既有插件的顺序与配置。
- 开发期间的旧记录有读取兼容与键迁移。来源不明的记录不能直接推断为个人日程；迁移报告须保留这种歧义。
- 不改桌面壳、更新器与机构仓；提醒另案。
- 桌面端行为需要独立验收；本提案的实现先在 Web 组装上验证。

## 开发拆分与验收

当前已提供周/月视图、日程与个人设置、ICS、来源登记与批量更新、提醒计算/调度适配器入口，以及十一个 Agent 工具。真实机构取数和独立机构入口留待后续；提醒到点记录与可选桌面系统通知已接入。

在插件目录准备 Runtime 并设置 `EDUWORK_TEST_RUNTIME` 后执行：

```sh
npm test
npm run test:browser
```

客户端发布构建沿用项目锁定工具链；测试中的 esbuild 只用于面板测试，不替代产品构建。仓库浏览器测试使用真实面板和服务，基础 UI 组件是测试替身，不能据此声称完整工作台或桌面已验收。

每个 PR 报告实际运行的测试、Runtime 版本与未验证范围。完整 Web 交互、模型会话、真实学校接口与 Electron 桌面分别验收；内部验证流水账不放入本提案。
