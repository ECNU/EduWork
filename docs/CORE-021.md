# DSH 0.2.1 集成

[English](CORE-021_EN.md)

当前构建配方选用 DSH `0.2.1-rc.3`，上游提交为 `1f81c047fc48fa190a683e469daa699857e9afe8`。`config/desktop-build.json` 指向 [候选锁](../third_party/dsh/candidate-v0.2.1-rc.3/LOCK.json)，npm Runtime、Host 和 Electron 源码分别校验。产品版本与内核版本独立；切换构建配方不会发布安装包或更新软件更新源。

## 能力与迁移

- rc.3 新增左侧栏、会话视图与右侧栏的“更多”菜单，沿用官方插件发现入口。创建插件沿用官方 Creator 会话和追加草稿机制，不自动发送；关闭“显示代码工作视图”或 Creator 时，菜单会提示对应设置入口，不自行开启功能。
- 采用官方未发送草稿恢复修复，保留会话草稿、附件与批注引用。DeepSeek API Key 模式使用官方动态模型目录；自定义服务端和目录仍按自己的配置运行。
- 沿用官方插件管理器、浏览器和 Office 能力。[选段引用与批注](../packages/dsh-annotation/README.md)以独立 npm 包预装，其他兼容客户端也可在插件页安装。新增官方 DeepSeek Search / Fetch API 提供者由原生设置管理；保留 EduWork 既有搜索默认值、用户选择及浏览器回退。
- Schedule 已并入官方基础组合。升级清除旧实验 Schedule bundle 的依赖和激活引用，保留任务存储、配置及其他插件；不再安装已停止发布的实验 bundle。
- 官方开发者工具以可选 bundle 提供，产品不默认启用请求采集。需要排错时按官方插件管理方式启用并检查导出内容。
- 文献和桌宠继续使用组件锁中已发布的 npm 版本。升级内核不会仅为改版本声明而重新发布插件。
- 官方统计、会话上报及反馈入口继续遵循已有发行策略。升级保留用户配置和会话；旧会话迁移不得覆盖历史文件，损坏日志不得被当作成功迁移。

## 适配边界

移除已经由上游实现的本机回环地址与随机端口补丁、文件引用重扫的撤销历史补丁。文件卡片展示、桌面集成和产品插件仍由 EduWork 提供。

活跃会话自动落盘引发的搜索冲突在此版本仍存在：锁定 npm 包中的查询实现与此前版本逐字节相同。因此保留[搜索一致性补丁](SESSION-SEARCH-BACKPORT.md)，继续检查完整文件哈希，并运行官方失败对照和修复回归。上游提供等价修复后应删除它。

同时保留设置导航图标、用户消息批注装饰入口与客户端模块元数据补丁。rc.3 仍会将差分更新备份硬链接清理产生的 ctime 变化视为代码重建；补丁仅跳过 mtime 与代码内容均未变化的重载。新增菜单的 Creator 可用性检查只是发行版开关适配，预设注册、工作区选择和草稿归属仍由官方实现管理。

普通启动沿用 DSH 的显示顺序：先在隐藏的主窗口中加载静态页面，等待 Host 就绪后显示主窗口，再由 BootPage 完成客户端插件加载并进入工作区。首次配置下载和旧版迁移会提前显示同一主窗口的 BootPage，展示准备状态，完成后继续进入工作区；此阶段跟随系统外观，主题设置加载后由上游接管。品牌适配与失败恢复保留，失败时使用专用恢复窗口。Dock、托盘和重复启动可以恢复当前的准备或恢复窗口；用户隐藏窗口后，后台准备完成不会强行将其重新显示。

## 构建与验证

[构建指南](BUILD.md)说明入口。各装配阶段从同一配方读取版本和提交，额外的输入文件哈希及 npm integrity 校验保持不变。`validate-pinned-dsh-source.yml` 在 Windows/macOS 验证实际 Host、Electron 桥接、已装配产品、设置与插件。

历史会话和语音适配探针也读取当前配方，使用新建的合成数据目录：

```sh
node scripts/probe-dsh-017.mjs --runtime <prepared-runtime> --output <new-evidence-directory>
node scripts/probe-dsh-017-speech.mjs --runtime <prepared-runtime> --output <another-new-directory>
```

这些探针不使用真实账号或模型推理，也不能替代原生桌面与正式升级验收。此前组合保留在 [DSH 0.2.0 集成说明](CORE-020.md)及对应锁中。
