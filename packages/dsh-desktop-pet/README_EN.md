# Desktop pet

[简体中文](README.md)

`@eduwork/dsh-desktop-pet` is an independently maintained and versioned DSH desktop-pet plugin. It includes Page (red and blue), Dafeiyu and Huashi, with character selection, size, status bubbles and idle napping. It shares the host's notification items with the tray and system notifications; clicking the pet opens a conversation that needs attention or has finished.

![Page](skins/eduwork-page/idle.svg)

## Use

EduWork bundles the plugin. Enable it under Settings → Desktop pet; it is off by default. Existing enabled state, character, size and position retain their original storage locations and are not reset by packaging it separately.

Other distributions can install the npm package and integrate it with a compatible desktop host:

```sh
npm install @eduwork/dsh-desktop-pet
```

**Host requirements: compatible DSH 0.2 APIs and the EduWork Electron desktop bridge.** The plugin contains settings, animation and artwork. The desktop shell provides the transparent floating window, click-through, dragging and position storage. Installing the package in a plain web app or a DSH client without this bridge does not supply a desktop window.

See the [desktop pet guide](https://github.com/ecnu/EduWork/blob/main/docs/DESKTOP_PET_EN.md) for usage and characters. Code is MIT licensed; see [skins/LICENSE](skins/LICENSE) for artwork sources and licenses.

## Host integration

- Register the Cordis service `desktopServices` with a `pet(request)` method. This is an injected runtime service, not an npm dependency to download.
- Add the package bundle to the DSH composition. It uses the stable entry `eduwork-desktop-pet`, with `enabled: false` by default. Existing EduWork product profiles insert the same entry; do not add a second instance.
- The shell loads `lib/page/` and `skins/` from the installed package and uses the existing notification items and open-conversation callback. Settings and shell menus share the existing show/hide action events.
- Tray and system notifications work independently of the pet switch. Approvals still happen in the app.

The service accepts two request shapes:

```js
{ action: 'configure', enabled, skin, frame, size, bubbles, sleep }
{ action: 'reset-position' }
```

Responses include `supported`; unsupported hosts return `{ supported: false }`. Stopping the plugin sends a disable request. See [desktop-services](https://github.com/ecnu/EduWork/blob/main/dsh-plugins/desktop-services/lib/index.js) and the [Electron pet window](https://github.com/ecnu/EduWork/blob/main/dsh-electron/src/desktop-pet.mjs) for the contract and window constraints.

## Develop

Run in this package directory:

```sh
npm ci
npm run check
npm pack --ignore-scripts
```

The build generates only the settings client, `lib/client.js`; Host modules and artwork ship in the package. Tests use the package's locked, real DSH dependencies by default. Set `EDUWORK_TEST_RUNTIME` to a product's `d` directory to test the assembled Runtime.

Page and Huashi are generated by `scripts/build-page-skins.mjs` and `scripts/build-huashi-skin.mjs`; after editing, run `npm run build:skins`. Dafeiyu uses whale-girl PNG sprites. New built-in characters are contributed through PRs; there is no character-package import UI.
