# 变更日志

**简体中文** | [English](CHANGELOG_EN.md)

记录本包的重要变更。项目使用语义化版本，1.0 之前的兼容性说明见[协议文档](docs/protocol.md)的版本一节。

## 0.1.0-dev — 未发布

本包**尚未发布到 npm，也还没有被装配进产品运行时**。下面记的是它当前包含什么、处于什么状态，
不是一份可以照抄的发布说明；发布说明由维护者确认后再写。

**已实现**

- 设备登记表、一次性配对邀请、设备凭据、活动连接管理。逻辑模块不做 I/O，时间由调用方传入，
  因此配对与撤销语义可以被直接测试。
- 门禁中继（`./listener`）：准入门禁、配对入口与等待页、逐设备撤销、实时通道的准入与切断。
  它是包内唯一持有文件和网络的模块，存储位置、监听端口与拓扑由使用方决定。
- 设备记录与凭据同放一处，使一次撤销不会留下两者互相矛盾。

**已实现但未接线**

- 操作面围栏（`./gate`）。决策表是完整的、有测试的，但**没有任何调用方**，因此本阶段不构成
  安全边界。原因见 README 的「已知取舍」：中继为了把手机送进宿主自己的门，必须把宿主的启动
  凭据交给它，手机因此持有完整的宿主浏览器会话，再在前面加一道 HTTP 中继也剥夺不掉宿主已经
  给出的权限。真正的硬闸只能由宿主自己的授权层执行。

**计划中，本包不含**

- 宿主侧执行围栏、装配进产品运行时、独立的 Web 客户端、端到端加密（含中继场景）。

**已知限制**

- 包内有两处可以记设备的地方（`DeviceRegistry` 与 `DeviceStore`），它们互不可见。合并它们属于
  把本包装配进产品的那一步，见 README 的「已知取舍」。
- 设备记录没有独立的撤销时间戳，`lastSeenAt` 同时承担「最后活跃」与「被撤销」两个含义。
