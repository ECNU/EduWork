# PDF 文件

只操作当前授权项目内的 `.pdf` 文件。工作流与内容判断由本 Skill 负责；确定性文件读写交给 `office_pdf` 工具。路径一律使用项目相对路径，不构造 Python 或 shell 命令。

## 工作流

1. 优先从用户请求和当前项目推断输入、输出与页面范围；未指定时默认处理全部相关页面并生成新文件、保留原文件。只有候选文件不唯一、页面范围会实质改变结果或用户明确要求覆盖时，才集中询问一次。
2. 读取已有文件时先调用 `office_pdf` 的 `inspect`，不要根据文件名猜测页数或内容。
3. 创建、合并或抽取页面后调用 `validate`；工具报告中 `valid` 为 `true` 才能报告结构验证通过。
4. 再调用 `inspect` 核对页数、页面尺寸和关键文本。
5. 只根据工具返回的 JSON 报告结果，并向用户提供 `relativePath`。

结构验证不等于视觉验证。脚本不会渲染页面；字体替换、文字溢出、分页观感和图片清晰度必须由上层预览或视觉能力另行检查。

## 工具契约

调用 `office_pdf`，参数为 `action`，按需提供 `input_path`、`output_path`、直接对象形式的 `spec`（旧版 `spec_json` 字符串仍兼容，二者只传一个）、`pages`；合并使用 `input_paths_json` 表示按顺序排列的项目相对路径数组。写操作由 DSH 权限层统一确认，PDF 产物会进入预览链路。私有 Python、依赖与脚本路径由插件管理，Agent 不应自行寻找或安装。

底层报告退出码：`0` 成功，`2` 参数或规格无效，`3` 文件不存在，`4` PDF 无法读取，`5` 输出失败，`6` 结构验证失败，`10` 缺少依赖。

## 创建规格

使用安全的结构化内容，不把用户文字当成 ReportLab 标记解析。`blocks` 支持 `heading`、`paragraph`、`bullet-list`、`table` 和 `page-break`：

```json
{
  "title": "会议纪要",
  "author": "Workspace",
  "subject": "项目周会",
  "page_size": "A4",
  "header": "项目团队",
  "footer": "第 {page} 页",
  "blocks": [
    {"type": "heading", "level": 1, "text": "会议纪要"},
    {"type": "paragraph", "text": "时间：2026 年 7 月 26 日"},
    {"type": "bullet-list", "items": ["确认范围", "安排负责人"]},
    {"type": "table", "header": true, "rows": [["事项", "负责人"], ["验收", "负责人 A"]]}
  ]
}
```

默认使用 ReportLab 内置 CJK CID 字体 `STSong-Light`，可生成中文但不会嵌入本机字体。需要指定品牌字体或严谨印刷交付时，应先取得已授权字体并走专门模板与视觉校验流程。

## 页面范围

`extract_pages --pages` 使用从 `1` 开始的页码，接受 `1,3-5` 或 `all`。范围必须递增且不能重复；输出为一个包含所选页面的新 PDF。合并按 `--input` 出现顺序追加页面，最多 50 个输入，合计不得超过 5000 页或 512 MiB。

## 依赖与边界

- Office 依赖和运行环境由宿主配置。报告缺失依赖，不自行安装、升级或更换宿主运行时。
- 不读取或写入项目外路径，不展开 `~`，不访问网络、凭据或用户独立 OpenCode 配置。
- 输入和生成的 PDF 最大 512 MiB、5000 页。设置页眉时上边距至少 16 mm，设置页脚时下边距至少 15 mm，避免与正文框重叠。
- 不处理加密 PDF、OCR、AcroForm、数字签名、PDF/A 合规和增量签名。修改已有 PDF 可能丢失书签、表单、签名或高级交互信息；保留原文件并说明。
- 文本抽取只反映 PDF 内容流可读文本。空结果不代表页面为空，也可能是扫描图片或特殊字体编码。
