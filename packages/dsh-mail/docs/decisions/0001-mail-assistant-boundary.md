# ADR 0001：邮件助手只做辅助读信与显式发信

**简体中文** | [English](0001-mail-assistant-boundary.en.md)

## 状态

已接受，2026-09-01。

## 背景

DSH Agent 需要在用户控制下读取和发送邮件，但标准 IMAP/SMTP 授权码通常拥有比单次任务更大的邮箱权限。若插件继续实现删除、移动、归档、标记、后台同步和自动回复，它会迅速变成一个能力宽泛但体验弱于专业客户端的邮箱产品，同时扩大误操作、提示注入和长期授权风险。

Gmail 等专用 OAuth2 API 与通用 IMAP/SMTP 的认证、权限和审计模型不同。当前目标是覆盖机构邮箱、单位邮箱和允许应用密码的通用服务，而不是伪装成统一邮箱客户端。

## 决策

一个插件同时提供设置界面和五个有界工具：目录发现、分页检索、只读读取、工作区附件下载和纯文本发信。读信与发信独立启用；IMAP 固定只读；SMTP 发信复用 DSH 原生权限预设；邮件内容始终不可信；凭据只进入 DSH Credential Provider。

删除、移动、归档、flags 写入、联系人、规则、后台轮询、自动回复、HTML 创作和计划发送不属于 v0.1。OAuth2 和多账号只能通过明确的新架构进入，不能把 token 或多个密码塞进普通设置。

## 结果

- 插件可以独立开源并被 Web 或桌面 DSH 组合复用，不绑定任何特定产品。
- 用户仍使用专业邮箱客户端管理邮箱状态，Agent 聚焦检索、理解和经授权的发信。
- Full Access 与 DSH 其他写工具保持一致，会跳过逐次审批；独立的发信开关仍是必要条件。
- 未来扩展若改变写操作或后台授权，必须新增 ADR、威胁模型和迁移说明。
