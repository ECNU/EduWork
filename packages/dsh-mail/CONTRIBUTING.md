# 贡献指南

**简体中文** | [English](CONTRIBUTING.en.md)

感谢参与。这个项目优先保证邮件安全边界，不以工具数量为目标。

## 开始开发

```bash
npm ci
npm run check
```

兼容性改动还应使用目标 DSH 的干净 Runtime 验收。对于当前基线 `0.1.5-rc.1`：

```bash
# DSH_RUNTIME_ROOT 指向干净的 0.1.5-rc.1 Runtime
npm run accept:dsh-015-rc1
```

自动化验收不会连接邮箱或发送邮件。真实互操作只使用专用测试账号和隔离 Profile，并只记录脱敏结论。

提交前请保证：

1. 新行为有无真实邮箱即可运行的自动化测试；
2. 涉及协议的改动同时覆盖取消、超时、大小上限和错误归一化；
3. 任何写操作都有清晰的能力开关、工作区/目标边界和人工确认策略；
4. 中英文文档同步；
5. 不提交邮箱地址、邮件样本、授权码、真实服务器日志或个人信息；
6. 不把删除、移动、自动回复、后台轮询等新边界混进修复型 PR。

版本遵循插件自己的 SemVer：兼容性修复和依赖维护使用 patch，新增向后兼容能力使用 minor，破坏工具或配置契约才使用 major；不机械跟随宿主产品版本。真实互操作测试请使用专用测试邮箱，并只提交脱敏后的结论和可复现的协议事实。安全问题不要走公开 issue，见 [SECURITY.md](SECURITY.md)。
