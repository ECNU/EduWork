# 选段引用与批注

[English](README_EN.md)

`@eduwork/dsh-annotation` 是一个可选的 DSH 插件：选中已完成回复中的文字，添加批注，在原回复底部查看编号，并与问题一起发送。引用、草稿保存与发送沿用 DSH 原生机制。

## 安装

在 EduWork 的「插件」页选择「添加插件」，填写 `@eduwork/dsh-annotation`，安装后启用。停用和卸载在同一页面完成。

需要提供官方 Chat 视图与输入框扩展的 DSH 客户端（`>=0.2.1-rc.2 <0.3.0-0`）。

## 使用

1. 在已结束回合的最终回复中选中文字，点出现的「＋ 批注」按钮。
2. 写批注（可留空），点「加入输入框」或按 Enter；Shift+Enter 换行。拼音组词时，Enter 只确认候选词，结束组词后再按 Enter 加入输入框。
3. 原回复底部出现批注编号；输入框保留原生引用块，并显示「N 条批注」。点击编号、引用块或汇总列表，可查看完整摘录、编辑或删除批注。
4. 可以继续添加多处批注，再输入问题一起发送；也可以只发送批注。发送后，当前草稿对应的编号与汇总自动清空。

引用块随草稿保存，可与普通文字、文件引用混用。刷新页面后会恢复待发送批注与来源编号。编号按当前输入框中的批注顺序排列，删除和原生撤销会同步更新。发送仍由客户端的原生流程完成，排队与插入运行中回合的行为遵循你的设置。

发送时，插件将每条批注整理为带编号的原文、可选备注和来源消息标识，并附上一份处理说明：请 AI 逐条回应批注，在对应回答中使用「【批注 1】」等文字编号。未填写备注的选段只作为上下文，不要求 AI 猜测问题。编号与本次输入框中的顺序对应；这是提示词约定，实际回答仍取决于模型，文字编号不会自动变成可点击的链接。复制到外部应用时仍使用简洁的引用文字。

编辑批注不会覆盖输入框里的其他内容；「取消」保留原批注。编辑时切换焦点不会自动关闭编辑框。若引用已变化或输入框正处于命令、提交状态，保存或删除会拒绝执行，保留输入供重试。只读预览可通过点击弹窗外、切换窗口或 Escape 关闭。

如果输入框暂时无法接收引用，批注编辑框会保留原文与输入内容，可稍后重试。浮层会跟随选中文字的位置，包括滚动和图片加载等排版变化。

## 功能边界

- 编号显示在原回复底部，随消息自然滚动；不在选中的每个字上绘制高亮或浮动编号。
- 只管理当前待发送草稿。已发送内容作为引用文字留在对话中，不维护另一套历史批注库。
- 新批注限定为官方 Chat 中已完成回合的最终回复；不对流式内容、工具输出、用户输入或侧栏文件挂编号。
- 摘录本身是完整快照。来源不在当前会话或暂未加载时，仍能从输入框查看和发送；旧版无来源信息的引用仍可查看、编辑和发送。

## 开发

```sh
node scripts/packages/manage.mjs install dsh-annotation
node scripts/packages/manage.mjs check dsh-annotation
```

插件通过官方 `conversation.chat.turnTail`、`conversation.input.left` 和 `conversation.input.overlay` 插槽添加界面。待发送批注和顺序来自公开的 `InputState.occurrences`；编辑、删除通过带版本校验的原生输入区间操作完成，不直接修改 Lexical 或整段草稿。`src/client/draft.js` 集中处理引用坐标换算及公开 Chat 快照中的来源消息解析。

选区只通过官方 Chat 行的 `data-chat-node-key` 查找消息身份，这是唯一的正文 DOM 适配点；不修改正文 DOM、不拦截发送、不全局扫描文字。宿主更换 Chat 行结构时需重新核对此适配点，不能回退为猜测来源。

`src/client/prompt.js` 通过官方 `ReferenceCodec.serialize` 格式化模型输入。编号和单次处理说明以原生提交的 `AbortSignal` 为弱引用键，依赖 DSH 0.2.1 按文档顺序逐个调用 codec 的行为；升级宿主时需复验重复引用、失败重试及并发会话的顺序。它不读取活动会话来猜序号、不改草稿、不接管发送，也不保存另一份批注历史。只发送已有的消息标识，不发送会话标识或编造原文偏移。
