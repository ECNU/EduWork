# 编辑消息

**简体中文** | [English](README_EN.md)

`@eduwork/dsh-message-edit` 让用户修改已经发出的消息，再从这条消息重新发送。用法和 Codex App 的“编辑消息”一样：改完发送后，对话从这条消息起换成新的内容，后面的旧消息和回复不再显示。

DSH 的会话记录只能追加，不能原地修改，所以插件用 DSH 原生的分叉实现：从这条消息之前分出一个新对话，把改过的消息作为新对话的下一轮发出，再让新对话接替原对话。原对话不做任何改动，移进归档，随时可以恢复。插件不修改 DSH 的 Runtime 或界面 bundle。

## 使用

在用户消息下方的按钮行，复制按钮旁边多了一个铅笔按钮。点击后，消息气泡换成编辑框：

- 文字可以直接修改。Enter 发送，Shift+Enter 换行，Esc 取消。输入法正在选词时，Enter 和 Esc 交给输入法。
- 原消息带的图片和文件列在编辑框上方，可以逐个移除。也可以选择、粘贴或拖入新的文件和图片：它们先上传到当前对话，和原生输入框一样先校验，校验失败时还没有创建新对话。文字、附件都删空时不能发送。
- 消息里引用的其他对话（`@对话`）会保留，编辑框下方显示“引用会话 · …”，和发出的消息一致。改动、删除或覆盖了引用文字时，这个引用就去掉；拿不准的情况一律去掉，不会留下用户已经删掉的引用。
- 发送后，新对话接替原对话：用户自己改过的标题会带过去，置顶的对话仍然置顶，正在看原对话的会跳到新对话，原对话移进归档。

几种情况的处理：

- 对话生成中，铅笔不可点，生成结束或停止后可以编辑。
- 回复生成中插入的消息（插话）不能单独编辑：它是在一轮进行到一半时加入的，那时可能已经执行了工具，没法从中间重来。插话下方显示一个不可点的铅笔，提示去编辑这一轮开头的消息；编辑开头那条消息时，编辑框会提示“这一轮还有 N 条插话，发送后会一起替换”。
- 同一个对话可以同时打开多条消息的编辑框。一条发出后，新对话里仍有的消息，它的草稿（包括还在上传的附件）跟着搬过去；新对话里已经没有的消息，草稿关闭。同一个对话一次只能发一条编辑，其余编辑框提示等待。
- 编辑框滚出视野或切换到别的对话，草稿和上传都保留。
- 子代理对话没有铅笔；没有分叉或发送权限时也不显示。

插件不会撤销已经执行过的文件修改和外部操作，编辑框里会提示这一点。

## 安装

在兼容 DSH 客户端的「插件」页添加 `@eduwork/dsh-message-edit`，安装并启用。需要 DSH `>=0.2.2-rc.1 <0.2.3-0`；本版本在官方 `0.2.2-rc.1` Runtime 上验证。

## 实现

- **主机端**（`src/index.js`、`src/remote.js`）：Typert Remote `eduworkMessageEdit/stageAttachments`。它把原对话里存好的附件在主机内重新登记成新对话的上传凭证，附件内容不经过浏览器。和 DSH 自己读附件的规则一样，存储引用按调用方对相应对话的权限处理；这次调用要读原对话、写新对话，所以访问控制两个对话都检查。owner 以外的调用方只有在访问策略明确放行这个方法时才能调用。
- **客户端**（`src/client/`）：
  - `index.jsx` 负责分叉、重发、接替原对话；分叉切点沿用 DSH 主机省略切点时的规则（`fork-boundary.js`），切点前继承的排队消息在发送前清掉。
  - `editor.jsx` 是编辑框。
  - `drafts.js` 在 React 外保存草稿和上传，因为 DSH 的对话列表是虚拟滚动，行会卸载。
  - `mentions.js` 跟踪引用其他对话的位置。
  - `steering.jsx` 给插话加不可用的铅笔。

依赖 DSH 的几处界面细节：

- 用户消息的按钮行没有插件扩展位。铅笔通过 `conversation.chat.user.before` 入口找到所在行，再挂进行内的按钮行（`[data-clock]`）。
- DSH 的插话行不渲染这个入口，所以插话的铅笔由常驻的 `shell.overlay` 组件按 `data-chat-flow-kind="steering"` 找到。

DSH 改了这些结构时，铅笔可能不显示，但不会影响对话本身。

## 本地开发

在本包目录执行，构建和测试使用锁定的 DSH Runtime：

```sh
npm ci
export EDUWORK_MESSAGE_EDIT_RUNTIME=../../third_party/dsh/candidate-v0.2.2-rc.1/npm-runtime
(cd "$EDUWORK_MESSAGE_EDIT_RUNTIME" && npm ci --ignore-scripts)
npm run check
```

浏览器验收用这个 Runtime 启动独立的 DSH 网页版，接入合成模型，用无头 Chromium 走一遍主要场景：

- 编辑中间的消息；
- 生成中和插话；
- 附件的移除和新增；
- 引用其他对话；
- 多个编辑框；
- 刷新后再检查一遍。

它不请求真实模型，DSH 数据、HOME 和默认工作区都放在输出目录里。需要先安装与 Runtime 中 `playwright-core` 版本匹配的 Chromium：

```sh
node scripts/browser-test.mjs --output <新的空目录>
```
