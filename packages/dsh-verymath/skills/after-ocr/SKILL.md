# After OCR

## DSH Integration Notes

- 本技能由 `@eduwork/dsh-verymath` 插件提供。`scripts/scan_markdown_ocr.py` 与 `merge_audit_logs.py`
  为纯标准库脚本，可直接经 shell 执行（建议加 `--format json` 供模型解析）；先确认
  `verymath_python_check` 报告 Python 可用。
- 扫描器只产生**候选清单**，不能替代本技能的逐段阅读纪律——工具输出后再按本技能的分段协议人工（模型）核对。
- 审校产物（审校日志、修订后的 Markdown）写入当前会话工作区；保护已有修订（SHA-256 记录规则见下文）。

## 核心原则

- 把 OCR Markdown 当作待验证材料。能够渲染只说明语法可能可接受，数学内容仍可能有误。
- 覆盖全文。候选扫描器用于提高定位效率，不能替代逐段阅读。
- 先确认语义，再修改公式。优先依据原始扫描件、局部推导、定义和跨处一致性。
- 不确定的数学内容保留原文并写入日志，标为需人工或原件确认。
- 保护已有人工修订。审查前记录哈希；不得用重新 OCR 的整篇输出覆盖现有文件。
- 所有修改记录位置、旧内容、判断依据和新内容。

## 开始前

1. 确认交付模式：`修订并记录`、`仅审查记录` 或 `限定区间审查`。用户只要求审查、报告或禁止改源文档时，跳过源文档修改。
2. 确认目标 Markdown、原始 PDF/扫描件、图片目录、同书其他 OCR 版本和已有校对稿。任务禁止读取某类辅助材料时，记录“已确认存在但未读取”或“未找到”。
3. 记录文件绝对路径、SHA-256、总行数、任务目标区间和首尾结构。
4. 若目标范围超过 2000 行，按连续 500–1200 行分段；为每段维护覆盖区间。
5. 阅读 [错误类型库](references/error-taxonomy.md)。需要生成正式审校记录时，再读 [日志与覆盖规范](references/audit-schema.md)。

## 通篇审校流程

### 1. 全文静态扫描

运行候选扫描器：

```bash
python3 /path/to/after-ocr/scripts/scan_markdown_ocr.py /absolute/path/to/input.md --format markdown
```

需要机器可读结果时使用 `--format json`。扫描器检查数学定界符、LaTeX 环境、可疑粘连命令、逐字母算子、Pandoc 转义、Unicode 数学符号和典型 OCR 残留。

限定区间审查时缩小输出范围：

```bash
python3 /path/to/after-ocr/scripts/scan_markdown_ocr.py /absolute/path/to/input.md --start-line 1 --end-line 1000 --format markdown
```

把输出当作候选清单。逐条结合上下文确认；扫描器未命中的行仍需阅读。

### 2. 连续分段阅读

按行号连续阅读全文，每段同时检查：

- 标题、目录、定理、定义、证明、列表、引用和编号层级；
- 行内数学与显示数学边界；
- 公式中的字符、字体、上下标、重音、定界符和关系符；
- 分式、根式、积分、求和、极限、矩阵、行列式、分段函数和数组；
- 变量在相邻公式中的一致性及推导方向；
- 正文错字、断词、异常空格、标点、页眉页脚、图内文字和重复页残留；
- 图片、表格、图题和正文的对应关系。

每完成一段立即记录覆盖区间。全文审校的最后一个区间必须到达文件末行；限定区间审查必须到达任务目标末行。

### 3. 定点对照原件

有原始 PDF 或扫描图片时，优先核对：

- 置信度低或会改变数学结论的候选；
- 分母、指数、积分上下限、不等号、否定符号和矩阵结构；
- 图表附近被压平的二维内容；
- 版本间存在差异的位置。

对候选页进行截图或局部读取。默认不重新 OCR 整本 PDF；只有用户明确要求生成新 OCR 版本时才执行整本推理。

PaddleOCR-VL MCP 或同类视觉 OCR 可用时，可以对单页或局部公式图像进行第二次识别。把该输出作为辅助证据，并与扫描图、数学上下文和其他版本交叉核验。

### 4. 修改

- `仅审查记录` 和 `限定区间审查` 且用户禁止修改时，直接生成日志与待确认列表，保留源文档哈希。
- 使用 `apply_patch` 做局部、可审查的修改。
- Markdown 文档的显示数学统一使用成对 `$$`；起止定界符各占一行，除非目标渲染器明确要求其他格式。
- 保留文档中语法有效的行内数学；需要规范化时，行内使用 `$...$`，显示数学使用成对 `$$`。
- 中文或英文说明进入数学环境时使用 `\text{...}`；算子使用合适的 TeX 命令。
- 根据语义选择 `aligned`、`cases`、`array`、`matrix`、`pmatrix`、`bmatrix` 或 `vmatrix`。
- 只在证据充分时修正数学内容。低置信度条目进入待确认列表。

### 5. 验证

1. 重新运行候选扫描器并审阅新增、消失和仍保留的候选。
2. 检查所有数学定界符、`\begin`/`\end`、`\left`/`\right` 是否平衡。
3. 对修改位置读取上下文，确认没有误伤邻近公式和段落。
4. 限定区间修订前记录区间外前缀/后缀哈希；修改造成行号移动时使用稳定锚点重定位，确认目标区间外字节流未变。
5. 若项目有渲染或转换命令，运行与风险相称的构建验证。
6. 在日志中写明覆盖到末行、已对照的原件页段、未解决问题和修改总数。
7. 限定区间任务分别记录目标区间是否完整覆盖、源文件是否覆盖到末行，禁止把样本末行写成全文末行。

## 多版本和大文档

- 完全相同的哈希只审一个主副本，并记录副本映射。
- 同书不同 OCR 模型版本分别审查；版本差异可帮助定位错误，版本一致不能单独证明内容正确。
- 大文档可由多个审查者按互不重叠的连续区间分工。每个区间保留独立日志，合并时检查边界。
- 用户要求双审时，两轮不得读取彼此日志。两轮结束后再按位置合并和裁决。
- 高可靠任务优先安排独立双审。现有八个完整样本中，按位置计的两轮共同命中率为 37.1%，另有 2527 个位置仅被一轮发现。
- A 轮可按正文顺序执行结构、边界、字符、语义检查；B 轮可逆序安排连续区间，并先查公式语义和二维结构，再查正文与版面，以降低相同的注意力遗漏。
- 多个审查者分割同一轮时，区间不得重叠或留缝，统一使用该轮标识；合并前保留每个分段日志和覆盖确认。

合并双审日志时运行：

```bash
python3 /path/to/after-ocr/scripts/merge_audit_logs.py pass-a.md pass-b.md --output merged.md
```

脚本按源文件与行号聚合候选，并保留每轮原始描述。最终裁决仍需检查同一行是否包含多个独立错误。

## 交付

- 修订后的 Markdown；
- 审校日志与全文覆盖确认；
- 低置信度待确认列表；
- 验证结果和仍存在的限制。
