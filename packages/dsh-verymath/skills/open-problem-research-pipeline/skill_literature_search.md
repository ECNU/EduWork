# 数学问题文献调研技能

## 功能

用户输入一个数学公开问题（猜想、未解决问题等），本skill自动完成：
1. 分析问题，识别核心数学概念、关键词、相关领域
2. 联网搜索该问题的研究现状、最新进展、已有结果
3. 整理输出结构化的文献调研报告

## 触发方式

### 方式一：标准Skill调用
在opencode.json中配置后，通过匹配描述自动触发。

### 方式二：触发词调用（推荐）
用户输入 `skill1: <数学问题描述>` 即可调用。

## 工作流程

### Step 0：问题精确化确认（新增）

**目标**：确保输入的数学问题被精确识别，避免因用户表述笼统导致分析偏差。

**流程**：
1. 对用户输入的问题描述进行**快速联网搜索**，查找最匹配的已知数学问题（猜想、定理、公开问题等）
2. 将搜索到的最接近的问题的**精确表述**呈现给用户，并询问："您要问的是这个问题吗？"
3. 用户确认后，进入 Step 1
4. 如果用户否认，要求用户提供更完整的问题信息，返回 Step 0

**注意**：如果用户输入的问题本身就非常明确（如 "Vizing猜想"、"黎曼猜想"），则跳过询问，直接进入 Step 1。

### Step 1：问题分析
- 提取问题中的核心数学对象、术语、已知条件
- 判断所属数学分支（数论/代数/几何/分析/拓扑/组合/概率/优化等）
- 生成初始搜索关键词（含中英文、同义词、缩写）

### Step 2：联网搜索
使用WebFetch工具搜索以下来源：
- **arXiv**：搜索相关预印本 (`https://arxiv.org/search/?query=...&searchtype=all`)
- **Wikipedia / MathWorld**：获取问题背景和已知结果
- **Google Scholar / Semantic Scholar**（可选）：搜索高质量引用
- **MathSciNet / zbMATH**（可选）：搜索经典文献

**来源核验要求**：

- 优先论文原文、作者主页、期刊/会议页面、arXiv 和权威数据库；
- 每条确认结果记录标题、作者、年份、URL 与访问日期；
- Wikipedia、MathWorld 和搜索摘要只作为线索，不能单独支撑“已解决”“仍开放”或最新进展；
- 无法访问论文全文时，明确区分“摘要声明”与“已检查正文”；
- 当前状态具有时效性，输出前必须重新核验；无法联网时标记 `unverified`。

### Step 3：信息整理
对搜索结果进行结构化提取：
- 问题起源与背景
- 目前已知的部分结果（特殊情况、边界条件、下界/上界等）
- 主要研究方向和流派
- 关键论文与主要贡献者
- 未解决的核心难点

### Step 4：输出报告
输出包含：

```json
{
  "problem": "问题原始描述",
  "domain": "所属数学分支",
  "status": "open/partially_solved/solved",
  "known_results": [
    {
      "result": "已知结果描述",
      "author": "作者",
      "year": "年份",
      "source": "arXiv/期刊等",
      "significance": "重要性说明"
    }
  ],
  "timeline": [
    {"year": "年份", "event": "重要进展"}
  ],
  "key_papers": [
    {"title": "标题", "author": "作者", "arxiv_id": "编号", "url": "链接"}
  ],
  "open_difficulties": ["难点1", "难点2"],
  "summary": "综合评述（1-2段）",
  "references": [
    {"title": "...", "authors": "...", "venue": "...", "url": "..."}
  ]
}
```

### Step 5：保存结果（自动持久化）

每次调用本skill，输出产物必须自动保存到以下位置，**不允许跳过保存步骤**：

**主存路径**（固定）：`outputs/literature_reports/`

**备用路径**（当主存路径不可写时）：当前工作目录下的 `outputs/literature_reports/`

**文件命名格式**：
```
<问题英文缩写（CamelCase）>_文献调研报告_<YYYY-MM-DD>.md
<问题英文缩写（CamelCase）>_文献调研报告_<YYYY-MM-DD>.json
```

**保存前的准备工作**：
- 若 `outputs/literature_reports/` 目录不存在，先用 `mkdir -p` 创建
- JSON 文件必须是合法 JSON（可由其他 skill 直接 `import`/`json.load` 消费）
- 如果同日期同名文件已存在，添加后缀 `_v2`、`_v3` 以避免覆盖

**输出产物清单**：
| 文件 | 用途 | 消费方 |
|------|------|--------|
| `*.md` | 人类可读的详细报告 | 直接反馈给用户 |
| `*.json` | 结构化数据（known_results/timeline/key_papers等） | 嵌入其他skill / 后续程序化调用 |

## 嵌入其他Skill

其他Skill通过以下方式调用本skill：

1. 在opencode.json中配置triggers，或在prompt中引用本skill描述
2. 在Agent prompt中添加：
   ```
   如需查阅数学问题的文献资料，请使用 literature-search skill。
   调用方式：以 "skill1:" 开头后接数学问题描述。
   ```
3. 程序化调用：在opencode.json中为当前skill配置 `{"command": "skill1:", "skill": "literature-search"}`
