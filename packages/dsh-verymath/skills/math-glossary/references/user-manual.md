# 数学术语库构建与管理 — 用户使用手册

## 一、概述

**math-glossary** 是一个从专业词汇文献中提取、构建和维护双语术语库的 AI 驱动工具。它通过 skill 的形式运行，用户只需在对话中提供源文件并回答几个引导性问题，即可完成术语库的构建、扩充和日常管理。

> **适配说明**：原始课程提交主要面向 Claude Code。VeryMath 课程版保留核心流程，
> 但不再要求专用提问工具、固定客户端目录或固定 DeepSeek 代理。脚本验证结果以
> package 测试为准；不同智能体的工作流效果仍需分别试用，不应由脚本测试外推。

### 核心能力

| 能力 | 说明 |
|------|------|
| **自动提取** | 从 PDF / Excel / TXT / Markdown 等格式的词汇文献中自动提取英中术语对 |
| **冲突裁决** | 同一术语在不同来源中有不同译法时，逐条让用户选择 |
| **Web 管理** | 一键启动本地 Web 界面，支持搜索、新增、修改、删除 |
| **变更日志** | 所有写操作自动记录到 Markdown 日志 |
| **三端同步** | JSON（源）→ Excel（导出）→ Web（展示）实时一致 |
| **学科无关** | 框架本身不绑定数学，可用于任何学科的双语术语管理 |

### 适用人群

- 需要从已有词汇书/词典中快速建库的翻译工作者
- 需要维护和迭代专业术语库的学科团队
- 需要为翻译 Agent 提供术语查询服务的开发者

## 二、快速开始

### 触发 Skill

在对话中输入以下任一关键词即可触发：

> 建术语库 / 整理数学词汇 / 从词典提取术语 / 术语库 / glossary / 词汇表 / 翻译术语管理

### 交互式引导流程

Skill 启动后会依次询问 **3 个问题**（每次一个，用方向键选择）：

```
第 1 问：术语来源 → 输入或拖拽源文件路径
第 2 问：库类型   → 可更新库（推荐）/ 固定库
第 3 问：文件类型 → 文本文档 / 结构化数据 / 电子词典 / 扫描件 PDF
```

- **可更新库**：构建完成后保持可维护状态，后续可搜索、新增、修改、删除
- **固定库**：只跑构建流程，完成后不保留维护能力

第 3 问之后，Skill 自动进入构建流程：解析源文件 → 提取术语 → 冲突检测 → 排序写入。

CSV/TSV/JSON/YAML 可直接使用离线入口：

```bash
python3 scripts/glossary_build.py "/path/to/source.csv"
```

默认输出到来源文件旁的 `术语库/glossary.json`。已有 JSON 不会被静默覆盖；确认
备份后才能显式添加 `--force`。其他格式继续由 Agent 按 `SKILL.md` 解析和复核。

## 三、术语库数据模型

每条术语是一个 JSON 对象，包含 9 个字段（含 `idx` 则为 10 个显示字段）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `term_id` | string | ✅ | 唯一标识。`en` 小写；别名行加 `__N` 后缀（如 `axiom of choice__1`） |
| `en` | string | ✅ | 英文术语原文 |
| `cn` | string | ✅ | 中文译名；别名行的 `cn` 即别名本身 |
| `pos` | string | ❌ | 词性，中文填写：名词 / 动词 / 形容词 / 副词 / 动词短语 等 |
| `field` | array | ❌ | 子领域，支持多值。如 `["代数拓扑", "代数几何"]` |
| `source` | string | ❌ | 来源参考书名称 |
| `examples` | array | ❌ | 例句列表，每项 `{en, cn}` |
| `created_at` | string | ✅ | 创建日期 `YYYY-MM-DD` |
| `updated_at` | string | ✅ | 更新日期 `YYYY-MM-DD` |
| `idx` | number | ✅ | 显示序号，自动维护，始终连续 |

### 别名处理

别名不作为字段存储，而是**展开为独立行**。例如：

```json
{"term_id": "axiom of choice", "en": "axiom of choice", "cn": "选择公理", ...},
{"term_id": "axiom of choice__1", "en": "axiom of choice", "cn": "AC", ...}
```

别名行与原术语共享相同的 `en`、`pos`、`field`、`source`、`examples`，仅 `cn` 和 `term_id` 不同。

### 排序规则

所有写操作后自动按 **英文首字母升序 → 中文首字母升序** 排序，并重新连续分配 `idx`。这确保别名行紧邻原术语。

## 四、构建新术语库

### 4.1 支持的源文件格式

| 大类 | 格式 | 解析策略 |
|------|------|----------|
| **文本文档** | 双语对照 PDF/TXT | 按行解析 "英文 中文" 对照关系 |
| | Excel (xlsx/csv) | 自动识别英文列和中文列 |
| | Markdown | 识别表格、列表、分隔符三种排版 |
| **结构化数据** | JSON | 字段自动映射，支持对象数组和键值对象两种结构 |
| | CSV | 自动检测分隔符和编码，按表头映射字段 |
| | YAML | 同 JSON 逻辑，先解析再映射 |
| **电子词典** | MDX | mdict-utils 解包为文本后提取 |
| **扫描件** | 扫描件 PDF | OCR 处理 |

### 4.2 构建流程

```
第 1 步：解析与提取
  → 从源文件中提取 en → cn 术语对
  → 为每条术语构造完整 JSON（pos/field/source/examples 暂为空）
  → source 字段记录来源文件名+行号

第 2 步：冲突检测与合并
  → 新术语（term_id 不存在）→ 直接加入
  → 重复术语（同一 term_id）→ 用新来源覆盖，旧值记入变更日志
  → 内部冲突（同一来源同一 term_id 多种译法）→ 列出让用户逐条裁决

第 3 步：排序与写入
  → 按 en → cn 排序
  → 重新连续分配 idx
  → 写入 glossary.json
  → 尝试导出 Excel（成功后删除旧 .xlsx，生成 glossary_YYYY-MM-DD.xlsx）
```

缺少 `openpyxl` 或导出失败时，JSON 仍然安全保留，但当前状态只能报告为
“JSON 已完成、Excel 待完成”。补齐依赖后再运行导出命令。

### 4.3 冲突裁决示例

```
发现 1 条术语存在冲突译法：

homology：
  · 同调（来源：新英汉数学词汇 第3章）
  · 同源性（来源：新英汉数学词汇 第7章）

请选择保留哪个译法？（输入 1 或 2）
```

## 五、Web 管理界面

构建完成后，从 `math-glossary` package 根目录启动管理界面：

```bash
python3 scripts/glossary_web.py \
  --glossary "/absolute/path/to/glossary.json"
```

### 5.1 启动与关闭

1. **启动**：运行上述命令，默认自动打开系统浏览器
2. **访问**：默认地址为 `http://localhost:7788`
3. **无图形界面**：添加 `--no-browser`，再手动访问输出的地址
4. **关闭**：优先在启动终端按 `Ctrl+C`；页面按钮仅作 best-effort 请求

界面没有身份认证，默认只监听本机。不得在未理解风险时将它暴露到局域网或公网。

### 5.2 搜索术语

- 在搜索框输入英文或中文关键词
- **前缀匹配**：输入 "man" 匹配 "manifold"、"mantissa" 等
- 支持同时匹配英文和中文
- 清空搜索框可恢复显示全部术语
- 点击搜索框右侧 ✕ 按钮一键清空

### 5.3 查看术语详情

- 点击术语所在行，弹出详情面板
- 显示完整字段：英文、中文、词性、子领域、来源、例句、创建/更新时间
- 详情面板顶部显示术语总数、来源数量、首字母分布统计

### 5.4 新增术语

1. 点击底部「+ 新增术语」按钮
2. 填写英文（必填）和中文（选填，可留空后补）
3. 系统自动查重：如果 `term_id` 已存在，弹出冲突提示，可选择覆盖或取消
4. 提交后自动排序 + 重新编号 + 尝试刷新 Excel + 记录日志；Excel 失败时显示
   “JSON 已完成、Excel 待完成”

### 5.5 修改术语

1. 在详情面板点击「编辑」按钮
2. 可修改字段：中文、词性、子领域、来源、例句
3. 提交时显示**修改前后对比**（红色旧值 → 绿色新值），二次确认后保存
4. `updated_at` 自动更新为当天日期

### 5.6 删除术语

1. 在详情面板点击「删除」按钮
2. 弹出确认对话框，显示将被删除的术语英文名
3. 确认后执行删除，自动排序 + 重新编号 + 尝试刷新 Excel + 记录日志；Excel
   失败时保留 JSON 并显示 warning

### 5.7 最近修改面板

页面底部展示最近 5 条操作记录，包含：
- 操作序号
- 操作时间
- 操作类型（新增 / 修改 / 删除，颜色区分）
- 术语英文名
- 修改详情

新增、修改、删除操作完成后自动刷新此面板，无需手动刷新页面。

## 六、扩充已有术语库

### 触发方式

在对话中输入精确指令：

> **我想扩充当前术语库**

只有这一句精确匹配才会触发扩充流程。

### 扩充流程

```
1. 输入用于扩充的源文件路径
2. 确认路径存在
3. 是否备份？→ 需要（推荐）/ 不需要
4. 执行构建流程（解析 → 提取 → 冲突检测 → 合并）
5. 自动刷新 Excel 并生成扩充记录
```

> **注意**：第 4 问（是否备份）是扩充流程的专属问题，初始构建不会出现。

### 扩充后操作

1. JSON 按 en → cn 排序后重新连续分配 idx
2. 自动导出 Excel（删除旧版本，只保留最新）
3. 生成 `扩充记录.md`
4. 如果选择了"需要备份"，先用 `glossary_backup.py` 备份

## 七、日志系统

术语库维护两套独立的日志文件：

### 7.1 修改记录（`修改记录.md`）

记录 Web 界面的**逐条操作**（新增 / 修改 / 删除）：

| 序号 | 时间 | 操作 | 术语 (en) | 修改详情 |
|------|------|------|-----------|----------|
| 1 | 2026-07-13 14:04:56 | 新增 | abacus | 新增: abacus → 算盘 |
| 2 | 2026-07-13 14:05:05 | 修改 | abacus | 中文：算盘 → 算盘（珠算） |
| 3 | 2026-07-13 14:05:30 | 删除 | abacus | 已删除 |

- 每次写操作自动追加一行
- 搜索和查看操作不记录
- 删除操作记录当时的 `idx` 序号

### 7.2 扩充记录（`扩充记录.md`）

记录**批量扩充**操作，包含两个表格：

**表格一 — 新增术语**（无新增时显示"本次扩充无新增术语"）：

| 序号 | 英文术语 | 中文译名 | 词性 | 子领域 | 来源 | 例句(英文) | 例句(中文) | 创建时间 | 更新时间 |

**表格二 — 替换术语**（无替换时显示"本次扩充无替换术语"）：

| 序号 | 词汇 | 替换前信息 | 替换后信息 | 变更原因 |

## 八、三端同步机制

术语库维护三重数据一致性保障：

```
           ┌──────────────┐
           │ glossary.json │  ← 唯一事实源（Single Source of Truth）
           └──────┬───────┘
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
   ┌────────┐ ┌────────┐ ┌─────────┐
   │ 内存排序 │ │ Excel  │ │ Web 前端 │
   │ + 重编号 │ │  导出   │ │  读取展示 │
   └────────┘ └────────┘ └─────────┘
```

每次写操作（新增/修改/删除）都经过 `_save_terms()` 统一处理：

1. 按 en → cn 两级排序
2. 重新连续分配 idx（从 1 开始）
3. 写入 `glossary.json`
4. 重新导出 `glossary_YYYY-MM-DD.xlsx`（删除旧版）
5. Web 前端下次请求时自动读取最新数据

**不要直接修改 Excel**，它只是导出产物。

## 九、部署新术语库

每次构建新的术语库后，按以下步骤启用 Web 管理界面：

### 部署步骤

1. **保留模板**：脚本继续位于 package 的 `scripts/`，无需复制到数据目录
2. **准备数据**：确认目标 `glossary.json` 路径和备份策略
3. **检查依赖**：

   ```bash
   python3 -c "import flask, openpyxl"
   ```

4. **缺失时安装**：向用户说明用途并获得确认后运行
   `python3 -m pip install -r requirements.txt`
5. **启动**：运行
   `python3 scripts/glossary_web.py --glossary "/absolute/path/to/glossary.json"`
6. **验证**：测试搜索、新增、编辑、删除、日志和 Excel 刷新

### 可定制项

| 项目 | 位置 | 说明 |
|------|------|------|
| 端口号 | CLI `--port` | 默认 7788，无需改源码 |
| 浏览器 | CLI `--no-browser` | 禁用自动打开 |
| 配色方案 | CSS 自定义属性 `--accent` 等 | 支持亮色/暗色双模式 |
| 页面标题 | HTML `<h1>` | 术语库名称 |
| 搜索匹配逻辑 | API `list_terms()` | 默认前缀匹配 |
| 数据字段 | 多处（见 web-template.md） | 增删字段需同步修改 7 处 |

## 十一、常见问题

### Q: 搜索不到某个术语？

当前搜索是**前缀匹配**，输入 "fold" 可以搜到 "manifold" 吗？不能——前缀匹配要求搜索词出现在术语开头。尝试输入术语的前几个字母，如 "man"。

### Q: 修改后序号乱了？

不会。每次写操作后 `_save_terms()` 自动按 en → cn 排序并重新连续编号，序号始终从 1 开始无断层。

### Q: 如何备份术语库？

- **扩充备份**：扩充流程的第 4 问可选择是否需要备份（选中后调用
  `scripts/glossary_backup.py` 生成 `glossary_backup_<时间戳>.json`）
- **手动备份**：复制 `glossary.json` 到安全位置即可

### Q: 可以修改 Excel 然后导入吗？

不推荐。JSON 是唯一事实源，Excel 只是导出产物。如果确实需要从 Excel 导入，使用 `glossary_export.py import` 命令。

### Q: 多个别名怎么处理？

同一术语的多个别名各自展开为一行，`term_id` 依次为 `en__1`、`en__2`……排序后它们会紧邻出现在原术语附近。

### Q: Web 界面端口被占用？

启动时添加 `--port <端口>`，例如：

```bash
python3 scripts/glossary_web.py \
  --glossary "/absolute/path/to/glossary.json" \
  --port 7790
```

### Q: 如何为翻译 Agent 提供术语查询？

将 `glossary.json` 路径告知翻译 Agent，让其阅读 `references/glossary-usage-guide.md`（第三方 Agent 调用指南）。Agent 只需读取 JSON 文件即可完成查词。


## 十二、局限性与未来改进

### 局限性

- **依赖格式规范**：当前解析策略仅对结构工整的对照文献（如《新英汉数学词汇》）效果最佳。面对排版混乱或含复杂数学符号的 PDF 时，解析准确率下降。
- **多义词仍需人工判断**：虽然 `field` 字段支持一词多义，但消歧依赖用户在录入时手动标注，系统暂无自动推荐能力。
- **单机部署**：Web 界面基于本地 Flask，仅支持单用户，不适合大规模协同维护。

### 未来改进

- **智能抽取**：引入 LLM 辅助术语抽取，从任意格式的源文件中自动识别英中对照关系，摆脱对工整排版的依赖。
- **上下文推荐**：为术语例句生成向量嵌入，翻译 Agent 调用时可根据原文句子动态推荐最匹配的义项。
- **协同与版本化**：将扁平 JSON 升级为轻量级数据库，支持多用户分支审校、历史回滚和变更对比（diff），使术语库真正具备团队协作能力。
